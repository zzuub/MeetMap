## 7. 서버 산출 로직

**산식과 상수는 여기서 정하지 않는다.** 제품 정책 값은 사용자가 정했고 지금은 FE 문서에 적혀 있어 그대로 인용한다. 이 장이 정하는 것은 **언제·어디서 계산하나**와 **경계에서 어떻게 동작하나**다.

### 7.1 산출값 목록

| 값 | 언제 계산하나 | 규칙 | 근거 |
| --- | --- | --- | --- |
| 모집 상태 · 마감 사유 · 지난 회차 | **요청 시** | 7.2 | D-07 · D-08 |
| 규모 · 시간대 · 표시 문자열 | 요청 시 | 7.3 | [FE 6.2·6.4][fe05] · [FE 12장][fe10] |
| 이번 주 · 그 이후 · 오늘 | 요청 시 | 7.3 | [`derive.ts`][derive] |
| 자격 · 가격 · 찜 여부 | 요청 시 (인증 주체마다) | 7.5 | [FE 6.1·6.4][fe05] · [decisions 4.44][dec] |
| 주최사 평점 · 후기 수 · 분포 · 인기 태그 | **저장 시** (후기 상태가 바뀌는 트랜잭션) | 7.6 | [FE 7.4·10.4][fe06] |
| `ratingScore` | 요청 시 (저장된 평점합·건수로) | 7.6 | [FE 6.2][fe05] · [decisions 4.20][dec] |
| 패싯 건수 | 요청 시 (목록과 한 스냅샷) | 7.7 | [decisions 4.28][dec] |
| 프로필 완성도 | 요청 시 | 7.8 | [FE 10.1][fe08] |
| `popularity` | **배치** | 7.9 — 산식 O-06 | [FE 12장][fe10] |
| 인기 검색어 스냅샷 · 대시보드 통계 | 배치 | 7.9 · 8장 | [FE 11.1][fe09] |

**시각에 기대는 값은 저장하지 않는다** (제안). 모집 상태·지난 회차·이번 주는 시계가 흐르면 바뀌므로, 저장하면 배치가 늦는 만큼 틀린 값이 나간다. 판정은 **KST** 로 하고 실행 환경의 타임존을 읽지 않는다 — 프론트와 같은 답을 내야 한다 ([`derive.ts`][derive]).

### 7.2 모집 상태 · 마감 사유 · 지난 회차

| 판정 | 규칙 |
| --- | --- |
| 지난 회차 | 개최 시각 ≤ 지금 |
| 응답의 `status` | 선언이 `마감` **이거나** 지난 회차면 `마감`, 아니면 `신청 가능` |
| 마감 사유 | 선언이 `마감`이면 `주최사 선언`, 선언은 `신청 가능`인데 지난 회차면 `개최 시각 경과` |
| 모집 중 (필터 `OPEN` · 홈) | 목록 노출 ∧ 응답 `status` 가 `신청 가능` (6.1) |

- 경계는 **개최 시각**이다(D-07 — "파티일, 시간이 되면"). 날짜가 아니라 시각이라, 오늘 저녁 회차는 저녁까지 목록에 남는다.
- 선언을 `신청 가능`으로 되돌려도 지난 회차는 `마감`이다 — 되돌리는 요청 자체를 `409` 로 거절한다 (P-06 · A-05).
- 찜 목록·검색 결과의 **표시 순서**(다가오는 순 → 지난 순)는 프론트가 KST **날짜**로 가른다 ([decisions 4.65·4.70][dec]) — 서버의 `지난 회차`(시각 기준)와 경계가 다르다. 서버는 그 두 목록의 순서를 약속하지 않으므로 충돌하지 않는다.

### 7.3 파생값

| 값 | 규칙 | 근거 |
| --- | --- | --- |
| 규모 | 남·여 정원 중 **큰 쪽**이 5 이하 `SMALL` / 6~9 `STANDARD` / 10 이상 `LARGE` | [FE 6.4][fe05] · [decisions 4.14][dec] |
| 시간대 | KST 시작 시각이 12시 전 `MORNING` / 12~17시 `AFTERNOON` / 17~21시 `DINNER` / 21시부터 `LATE_NIGHT`. **경계는 시작 시각** — 12:00 은 오후, 21:00 은 심야 | [FE 6.2][fe05] |
| `dateLabel` · `timeLabel` | KST `9/5(토)` · `19:30` 모양 | [FE 12장][fe10] |
| 이번 주 | KST **월 00:00 ~ 일 23:59:59.999**. `그 이후`는 이번 주가 끝난 뒤 | [`derive.ts`][derive] `weekRangeKst` · [FE 6.4][fe05] |
| 오늘 | KST 달력 날짜가 같다 — 시각이 아니라 날짜 | [`derive.ts`][derive] `isTodayKst` |

### 7.4 정렬

| 정렬 | 1차 키 | 2차 · 동률 | 근거 |
| --- | --- | --- | --- |
| `popular` (기본) | `popularity` 내림차순 | id | [FE 6.2][fe05] · O-06 |
| `latest` | 등록일 내림차순 — **회차의 최초 공개 시각**이지 개최일도 주최사 입점일도 아니다 | id | [FE 6.1][fe05] · O-26 |
| `rating` | 주최사 `ratingScore` 내림차순 | **개최일 가까운 순**, 그다음 id | [FE 6.2][fe05] |
| `priceAsc` · `priceDesc` | **인증 주체 성별의** 참가비 | id | [FE 6.2][fe05] |

- 동률을 id 로 끊는다 (제안) — 커서 페이지가 새로고침마다 흔들리지 않게.
- 가격 정렬에서 **가격 미확인(`null`)은 방향과 무관하게 맨 뒤** (제안) — 오름차순 맨 앞에 미확인이 몰리면 가장 싼 것처럼 보인다. 확정 O-07.
- 게스트·프로필 없는 사용자의 가격 정렬은 **무시하고 기본 정렬로** 답한다 (제안) — 프론트의 파싱이 게스트에게 이 값을 "모르는 값"으로 떨어뜨리는 것과 같은 결과다 ([decisions 4.30][dec]). 확정 O-08.
- `rating` 정렬에서 같은 주최사 회차가 뭉치는 것은 아직 막지 않는다 — 2차 정렬만 둔다 ([FE 6.2][fe05] · FE 16장).

### 7.5 거르기 축과 인증 주체

**인증 주체 = 로그인한 USER 의 프로필**(성별·출생연도)이다. 세션이 아니다 — 로그인만 하고 프로필을 건너뛴 사람에게는 판정 근거가 없다 ([decisions 4.44][dec]). 프로필이 없으면 게스트와 같게 다룬다 ([FE 6.4][fe05]).

| 축 | 규칙 | 근거 |
| --- | --- | --- |
| 자격 `eligibleOnly` | **세 상태** — 값이 없으면 기본값(프로필이 있으면 켜짐), `0` 은 끔, `1` 은 켬. 켜지면 출생연도가 참가 연령 범위에 들고 **내 성별 정원이 0 이 아닌** 회차만 | [FE 6.1·6.4][fe05] · [decisions 4.25][dec] |
| 가격 상한 `maxPrice` | 내 성별 참가비 ≤ 상한. **가격 미확인은 뺀다**. 상한은 `PRICE_CAPS` 값만 | [FE 6.1][fe05] · [FE 12장][fe10] |
| 일정 `when` | `THIS_WEEK` 이번 주 개최, `LATER` 이번 주 이후 | [FE 6.4][fe05] |
| 시간대 · 규모 | 7.3 의 파생값으로 거른다. 저장된 사본을 쓰지 않는다 | [decisions 4.35][dec] 3단 |
| 모집 상태 `OPEN` | 모집 중(7.2) | [FE 6.4][fe05] |
| 분위기 | 고른 태그 중 **하나라도** 달린 회차 (OR) | [FE 6.4][fe05] |
| 지역 · 구 · 주최사 | 같은 값 | [FE 6.1][fe05] |
| 찜 여부 | 인증 주체의 찜 행이 있으면 참 | [`endpoints.ts`][ep] |

홈 섹션 B(`내 나이대`)는 자격과 다르다 — **출생연도만** 본다 ([FE 5.3][fe04]). 둘을 한 함수로 합치지 않는다.

### 7.6 주최사 평점

| 값 | 규칙 | 근거 |
| --- | --- | --- |
| 후기 수 `n` · 평점합 · 분포(1~5) | `게시` 후기로 센다 (4.8 · O-09) | [FE 10.4][fe08] |
| `rating` | 평점합 ÷ n. **n < 5 면 `null`** — 표시 임계는 서버가 적용해서 내린다. 화면마다 다시 세면 어긋난다 | [FE 12장][fe10] · [FE 7.4][fe06] |
| `ratingScore` | `(C × m + 평점합) / (C + n)`, **C = 10, m = 4.3**. 후기 0건이면 m 이 되어 중간에 선다 | [FE 6.2][fe05] · [decisions 4.20][dec] |
| 인기 태그 | 달린 횟수 상위 5개와 분류 | [FE 10.4][fe08] |

- 후기 목록 요약 블록의 평균(`ReviewSummary.average`)도 `rating` 과 같은 값을 쓴다 — 5건 미만이면 `null` (제안 · O-62). FE 12장은 이 필드를 `number` 로 두고 숫자 숨김([FE 10.4][fe08])을 화면에 맡겼다.
- **`ratingScore` 는 저장하지 않고 조회 때 계산한다** (제안) — 평점합과 건수만 집계에 둔다. C·m 을 바꿔도 데이터를 고칠 필요가 없어, 프론트 쪽 결정(4.20 "되돌리기 쉬운 결정")이 서버에서도 그대로 쉽다. m 을 실측 평균으로 바꾸는 시점은 O-78.
- `ratingScore` 는 정렬에만 쓰고 **공개 응답에 싣지 않는다** (R-09 · O-61).

### 7.7 패싯 건수

- 시간대별·구별 건수를 **자기 축만 풀고** 나머지 조건은 그대로 두고 센다 — 구를 골라도 시간대 건수는 그 구 안에서, 구 건수는 그 구를 풀고 센다 ([decisions 4.28][dec]).
- 0건인 값은 빼고 내린다 — 화면이 0건 선택지를 그리지 않는다 ([FE 6.2·6.3][fe05]). 단 **지금 고른 값은 0건이어도 싣는다** — 결과가 왜 비었는지 설명할 자리가 그것이다 (제안).
- 목록과 **한 스냅샷**에서 센다 (R-02) — 따로 세면 선택한 구의 건수와 결과 수가 어긋날 수 있다.

### 7.8 프로필 완성도

마이페이지 체크리스트 네 항목 — 닉네임 · 출생연도·성별 · 선호 지역 · 프로필 사진 — 중 채운 수 ÷ 4 × 100, 반올림 (제안 — FE 10.1 이 "항목 목록은 서버 정의 TBD"로 넘겼고, 같은 절이 이 네 항목을 화면에 그렸다).

### 7.9 배치 산출 — 산식이 정해지면 채운다

| 값 | 정해진 것 | 정해지지 않은 것 |
| --- | --- | --- |
| `popularity` | 인기순 정렬과 홈 섹션 A 의 키 | 산식 전부 (O-06). 입력 후보인 조회·찜·이동은 이미 기록한다(4.15) — **그 조합을 여기서 정하지 않는다** |
| 인기 검색어 | 스냅샷 모양·결과 보장·거르기 (R-08), 간격 가안 1시간 | 몇 시간 치 검색을 세나 (O-77) |
| 대시보드 통계 | 조회·찜·이동·이동률 (6.6) | 조회 정의(O-05), 기간·증감 기준(O-68) |
