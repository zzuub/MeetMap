### 4.10 엔티티 한눈에

```
계정 ─┬─ 로그인 수단 (비밀번호 · 카카오 · 네이버 · 구글 · 2FA)
      ├─ 멤버십 (역할 하나 + 상태)
      ├─ [USER]     프로필 · 선호 지역 · 약관 동의 이력 · 알림 설정 · 찜 · 알림
      └─ [PROVIDER] 담당 연결 ── 주최사 (04a) · 가입 신청
초대 ──(수락)──▶ 계정
신고 ── 신고 건 ── 후기 (04a)
활동 로그 · 신청 URL 이동 기록 · 조회 기록 · 검색 기록
```

| 엔티티 | 모듈 | 관계 |
| --- | --- | --- |
| 계정 · 로그인 수단 · 멤버십 | `account` | 계정 1 : N 로그인 수단, 계정 1 : 1 멤버십(MVP1) |
| 초대 | `account` | 수락되면 계정 1개 |
| 가입 신청 · 담당 연결 | `provider` | 계정 1 : 1, 주최사 1 : 1(MVP1) |
| 프로필 · 선호 지역 · 약관 이력 · 알림 설정 · 찜 | `user` | 계정 1 : 1 / 1 : N |
| 알림 | `notification` | 계정 1 : N |
| 신고 · 신고 건 | `moderation` | 후기 1 : N 신고, 신고 건 1 : N 신고 |
| 활동 로그 | `audit` | 운영자 계정 1 : N |
| 이동 · 조회 · 검색 기록 | `tracking` · `search` | 회차 1 : N |

### 4.11 계정 · 로그인 수단 · 멤버십

**계정**

| 필드 | 규칙 | 근거 |
| --- | --- | --- |
| 상태 | `정상` / `탈퇴`. 정지는 계정이 아니라 멤버십의 상태다 | [목업 AdminManage][mk-adminm] · [FE `MembershipStatus`][acc] |
| 이메일 | `null` 허용 — 소셜 가입은 이메일을 못 받을 수 있다 | [FE `Account`][acc] |
| 가입 시각 · 최근 접속 시각 | 회원 관리 화면이 보여준다 | [목업 AdminManage][mk-adminm] |

**로그인 수단** — 계정 하나에 여럿이 묶인다 (D-01)

| 필드 | 규칙 |
| --- | --- |
| 종류 | `PASSWORD` · `KAKAO` · `NAVER` · `GOOGLE` |
| 외부 식별자 | 소셜 신원. **(종류, 외부 식별자)는 유일하다** — 소셜 신원 하나는 계정 하나에만 묶인다 |
| 비밀번호 | 로그인 이메일(유일), 해시, 임시 비밀번호 여부, 이전 비밀번호 이력(재사용 금지 — 몇 개까지는 O-35) |
| 2FA | 운영자 전용. 방식 O-33 |

| 역할 | 허용하는 로그인 수단 | 근거 |
| --- | --- | --- |
| USER | 소셜 하나 이상. 비밀번호는 없다 | [FE 3.1][fe03] · D-01 |
| PROVIDER | **비밀번호 필수** + 소셜 연동(선택). 계정 이메일은 운영자만 바꾼다 | D-01 · [목업 ProviderManage][mk-provm] |
| ADMIN | 비밀번호 + 2FA. 소셜 없음 | [decisions 4.5][dec] · D-09 |

⚠️ FE `Account` 타입은 로그인 수단을 하나(`authProvider`)만 든다. 서버 모델이 1 : N 으로 바뀌었다 → O-37.

**멤버십**

| 필드 | 규칙 | 근거 |
| --- | --- | --- |
| 역할 | `USER` · `PROVIDER` · `ADMIN` | [dev-plan 3.2][plan] |
| 상태 | `ACTIVE` · `PENDING` · `REJECTED` · `SUSPENDED` — 전이는 5.1 | [FE `MembershipStatus`][acc] |
| 부여 시각 | — | 상동 |

- **MVP1 은 계정당 멤버십 하나다** (D-01). 표를 따로 둔 것은 역할이 늘어날 여지를 남기기 위해서다 ([decisions 4.4][dec]).
- **`isNewUser` 는 저장하지 않는다.** USER 이고 필수 약관 동의 이력이 없으면 참이다 (제안) — 약관 제출이 이 값을 내리는 자리라서([decisions 4.43][dec]) 둘을 따로 두면 어긋날 길만 생긴다.

### 4.12 초대 · 가입 신청 · 담당 연결

**초대** — 운영자가 발급한다

| 필드 | 규칙 | 근거 |
| --- | --- | --- |
| 대상 역할 | `PROVIDER` / `ADMIN` | [목업 Admin][mk-admin] · [dev-plan 3.3][plan] |
| 받는 이메일 · 연결할 주최사 | 주최사 초대는 연결할 주최사 프로필을 함께 든다 — 운영자가 대신 만든 프로필을 넘겨받는 경로다 | D-01 |
| 토큰 | 추측할 수 없는 난수. 원문을 저장하지 않고 해시만 둔다 (제안) | — |
| 만료 · 수락 시각 · 발급자 | 유효기간과 임시 비밀번호 발송 방식은 O-34 | [목업 Admin][mk-admin] |

목업의 주최사 계정 발급 폼은 한 화면에서 여러 곳에 쓴다 — 사업자·담당자 정보는 **주최사**(4.3), 계약 기간·이미지 사용 범위·비고는 **동의·계약 기록**(4.4), 계정 이메일은 **초대**다.

**가입 신청** — 주최사 셀프 가입 (D-01)

| 필드 | 규칙 | 근거 |
| --- | --- | --- |
| 신청 계정 | 비밀번호로 만든 계정 + `PENDING` 멤버십 | D-01 |
| 사업자 정보 | 상호·사업자등록번호 필수. 진위 확인 O-52. 사업자가 없는 개인 주최자 O-17 | [목업 AdminManage][mk-adminm] · [dev-plan 3.3][plan] |
| 담당자명 · 연락처 · 운영 지역 | 목업 신청 카드의 항목. 운영 지역은 텍스트 | [목업 AdminManage][mk-adminm] |
| 상태 | `승인 대기` / `승인` / `반려` — 멤버십 상태와 함께 움직인다 | 상동 |
| 결정자 · 시각 · 반려 사유 | 사유 입력과 재신청은 O-16 | — |
| 연결 결과 | 기존 주최사 프로필 / 새 프로필 | D-01 |

**담당 연결** — PROVIDER 계정 ↔ 주최사

- MVP1 은 **주최사당 계정 하나**(목업 `계정 이메일` 1칸 — O-24), 계정당 주최사 하나다 (제안).
- 주최사 계정의 모든 쓰기는 이 연결의 주최사 범위 안에서만 된다 (5.5).

### 4.13 USER 개인 데이터

**프로필**

| 필드 | 규칙 | 근거 |
| --- | --- | --- |
| 닉네임 | 앞뒤 공백을 버리고 1~12자. 중복 허용 O-53 | [FE 3.4][fe03] · [FE `profileInput`][pin] |
| 출생연도 | 1975~2007 | [FE 3.4][fe03] |
| 성별 | `F` / `M` | [FE 12장][fe10] |
| 프로필 사진 | `null` 허용. 입력 화면이 아직 없다 | [FE 16장][fe14] |
| 완성도 `completionRate` | 파생 — 7장 | [FE 10.1][fe08] |

- **프로필이 "있다" = 닉네임·성별이 저장됐다.** 없으면 `GET /users/me/profile` 은 `404` 다 — 지역만 든 반쪽 프로필을 내려주면 가격·자격 판정이 근거 없이 열린다 ([`endpoints.ts`][ep] · [decisions 4.44][dec]).

**선호 지역** — 프로필과 **별개 행**이다

- 지역 마스터 8곳 안에서, 중복을 빼고 최대 3개. 서버도 거른다.
- **프로필이 없어도 저장한다** — 위치 권한 화면은 프로필을 건너뛴 사용자에게도 지역을 묻는다.
- 프로필 저장은 이 값을 **통째로 덮어쓴다** ([`endpoints.ts`][ep] · [decisions 4.53][dec]).

**약관 동의 이력**

- 항목: 만 19세 이상·서비스 이용약관·개인정보 수집 및 이용(필수), 마케팅 정보 수신(선택) ([FE 3.2][fe03]).
- 동의·철회를 **쌓기만 한다.** 마케팅 동의는 나중에 바꿀 수 있다 ([FE 10.3][fe08]). 약관 버전 관리 O-54, 알림 설정과의 연동 O-22.

**알림 설정** — 계정당 한 행. 없으면 기본값으로 만든다

| 항목 | 기본값 | 근거 |
| --- | --- | --- |
| 관심지역 신규 소개팅 | ON | [FE 10.3][fe08] |
| 후기 작성 요청 | ON | 상동 |
| 추천 소개팅 소식 (주 1회) | OFF | 상동 |
| 방해 금지 시간 | `23_08` (`OFF` · `23_08` · `00_09`) | 상동 |

**찜**

- (계정, 회차)는 유일하다. `PUT` 이 찜, `DELETE` 가 해제 — 멱등이다 ([decisions 4.59][dec]).
- **마감·지난 회차도 남는다** ([FE 9장][fe07] · [decisions 4.65][dec]). 찜한 시각을 저장해 두면 나중에 `찜한 순` 정렬을 약속할 수 있다 ([decisions 4.65][dec] 번복 조건).
- 해제는 행을 지운다 (제안). 기간별 찜 수 추이가 필요하면 별도 기록을 둔다 — 조회수 정의(O-05)와 함께 8장에서 정한다.

**알림** — 계정, 종류(`new` · `review` · `info`), 태그, 제목, 본문, 딥링크, 생성 시각, 읽은 시각 ([FE 12장][fe10]). 보존 기간 O-23.

### 4.14 신고 · 신고 건 · 활동 로그

**신고**

| 필드 | 규칙 | 근거 |
| --- | --- | --- |
| 후기 · 신고자 · 신고자 역할 | (후기, 신고자)는 유일하다 (제안) | — |
| 자격 | USER 는 그 후기 회차의 참여 인증, PROVIDER 는 자기 주최사 회차의 후기 | D-05 |
| 사유 | 특정인 비방 · 허위 사실 · 개인정보 노출 · 광고성 게시물 | [목업 AdminManage][mk-adminm] |
| 내용 · 시각 | 운영자에게 보이는 신고 내용 | 상동 |

**신고 건** — 후기 한 건에 쌓인 신고를 묶어 처리하는 단위

| 필드 | 규칙 | 근거 |
| --- | --- | --- |
| 접수번호 | 목업 `R-…` 형식 | [목업 AdminManage][mk-adminm] |
| 처리 상태 | `접수` · `검토중` · `보류` · `삭제` · `기각` | 상동 |
| 처리 메모 | **내부 전용** — 회원에게 노출하지 않는다 | 상동 |
| 처리자 · 시각 | 결과는 신고자와 작성자에게 안내한다 → 8장 | 상동 |

- 처리 상태가 후기 상태를 정한다 — `삭제` → 후기 `삭제`, `기각` → 그대로 `게시`, `보류` → O-09. 종결 뒤 재신고는 O-10.
- **신고만으로는 후기를 숨기지 않는다.** 숨김·삭제는 운영자 처리의 결과로만 생긴다 (D-05).
- 회원 관리의 `신고 누적 N건`은 그 회원이 쓴 후기에 달린 신고 수다 — 파생값이다.

**활동 로그** — 추가만 한다. 고치지도 지우지도 않는다

| 필드 | 규칙 | 근거 |
| --- | --- | --- |
| 시각 · 행위자 | 운영자 계정 | [목업 AdminManage][mk-adminm] |
| 종류 | `승인·반려` · `계정` · `신고` (목업 필터 3종) | 상동 |
| 행위 · 대상 · 사유 | 대상은 종류·id·표시 이름을 함께 남긴다 — 대상이 나중에 이름을 바꿔도 기록이 읽힌다 | 상동 |

남기는 행위: 검수 승인·반려, 운영자 대신 등록·수정, 초대 발급, 가입 승인·반려, 회원 상태 변경, 후기 보류·삭제, 신고 처리 상태 변경, 동의·계약 기록 변경, **운영자 로그인**("접속 기록은 감사 로그에 저장됩니다" — [목업 Admin][mk-admin]).

### 4.15 통계 원천 기록

| 기록 | 담는 것 | 쓰는 곳 | 근거 |
| --- | --- | --- | --- |
| 신청 URL 이동 | 회차, 계정(게스트면 없음), 시각. 추가만 한다 | 대시보드 `신청 URL 이동`·이동률 | [FE 7.3][fe06] · D-02 |
| 조회 | 회차, 시각 — 무엇을 1회로 세나는 O-05 | 대시보드 `조회수` | [목업 Provider][mk-prov] |
| 검색 | 검색어, 시각. **계정은 남기지 않는다** (제안) — 인기 검색어에 필요 없다 | 인기 검색어 Top 6·증감·기준 시각 | [FE 11.1][fe09] |
| 일별 집계 | 주최사·회차별 조회·찜·이동 | 주최사·운영 대시보드 | [목업 ProviderManage][mk-provm] |

집계 주기는 8장, 원천 기록의 보존 기간은 O-23.

### 4.16 삭제 · 이력 보존 (계정 · 운영)

좌표와 참석자 개인 정보는 **애초에 받지 않는다** (1.3). 아래는 받은 것의 처리다.

| 엔티티 | 지우는 방식 | 이유 · 미결 |
| --- | --- | --- |
| 계정 (탈퇴) | 상태 `탈퇴`. 개인정보 파기·익명화 범위와 재가입은 O-13 | 법정 보존 O-46 |
| 로그인 수단 · 프로필 · 선호 지역 · 알림 설정 · 찜 | 탈퇴 시 파기 | O-13 |
| 멤버십 | 상태로 남긴다 | 정지·반려 이력이 운영 근거다 |
| 약관 동의 이력 | **지우지 않는다** | 동의의 증거다. 보존 기간 O-46 |
| 알림 | 보존 기간이 지나면 지운다 | O-23 |
| 초대 | 수락·만료 뒤에도 남긴다 (제안) | 누가 누구를 초대했는지가 감사 대상이다 |
| 가입 신청 | 지우지 않는다 | 반려 이력 |
| 신고 · 신고 건 | 지우지 않는다 | 처리의 근거다 |
| 활동 로그 | **지우지 않는다. 고치지도 않는다** | 보존 기간 O-46 |
| 이동 · 조회 · 검색 기록 | 집계 뒤 원천 기록 처리 | O-23 |
