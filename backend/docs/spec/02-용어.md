## 2. 도메인 용어

**프론트와 같은 말을 쓴다.** 코드 식별자도 프론트 타입([FE 12장][fe10])의 필드명을 따른다 — 서버와 화면이 같은 값을 다른 이름으로 부르면 계약 대조가 번역 작업이 된다. 이 장에 없는 말을 새로 만들 때는 여기에 먼저 적는다.

### 2.1 용어표

**사람 · 조직**

### 2.2 헷갈리는 짝

| 짝 | 차이 | 섞으면 |
| --- | --- | --- |
| 주최사 ↔ 주최사 계정 | 주최사는 조직, 계정은 로그인 주체다. 단계 ①의 주최사에는 계정이 없다 | 계정 정지를 주최사 비공개로 처리한다 (O-18) |
| 검수 ↔ 가입 승인 ↔ 선발 | 검수는 회차 개정본을, 가입 승인은 주최사 계정을 운영자가 판단한다. 선발은 주최사가 참가자를 고르는 일이다 | 문서마다 "심사"를 둘에 쓴다 — 사업자 심사([dev-plan 1장·P7-1][plan])와 참가자 심사([목업 Provider][mk-prov] 등록 폼 · [decisions 4.6][dec]). 서버 코드에서는 이 말을 쓰지 않는다 (제안) |
| 평점 ↔ 정렬 점수 | 평점은 보여주는 값(원본 평균), 정렬 점수는 줄 세우는 값 | 두 숫자가 화면에 나란히 보이면 설명할 수 없다 ([decisions 4.20][dec]) |
| 신청 ↔ 신청 URL 이동 | 서버는 이동만 안다 | "신청 수"라 부르면 주최사가 실제 신청 수로 읽는다 |
| 지역(`area`) ↔ 구(`district`) | 8곳 마스터(선호 지역) / 25개 구(지역 필터). 별개 축이다 | 한 필드로 합치면 둘 다 깨진다 ([FE 6.1][fe05]) |
| 선언 마감 ↔ 지난 회차 | 선언 마감은 개최 전일 수 있고 목록에 남는다. 지난 회차는 목록에서 빠진다 | 마감한 회차가 개최 전에 목록에서 사라진다 |
| 등록일 ↔ 개최 시각 ↔ 주최사 등록일 | `createdAt`(회차 공개) / `date`(개최) / `registeredAt`(주최사가 서비스에 등록된 날) | 최신순이 개최 임박순이나 입점순이 된다 ([FE 6.1][fe05]) |
| 후기의 작성 대상 ↔ 집계 대상 | `eventId`(참여 인증 단위) / `providerId`(평점 단위) | 회차 평점이 되살아난다 ([decisions 4.19][dec]) |
| 동의 ↔ 계약 | 같은 기록의 두 부분이다. 동의는 단계 ①부터 있고 없으면 등록 자체가 안 된다. 계약(기간·정산)은 없을 수 있다 | 동의 없이 계약만 보고 이미지를 쓴다 |
