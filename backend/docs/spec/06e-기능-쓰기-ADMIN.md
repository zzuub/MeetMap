서식은 [6.0](06a-기능-읽기-공개.md) 을 따른다. 원본은 [목업 Admin][mk-admin] · [AdminManage][mk-adminm] 와, 목업이 없는 운영자 등록 경로에 한해 [dev-plan Phase 6][plan] 이다.

**모든 운영 쓰기에 걸리는 규칙 둘.**
1. **2FA 까지 마친 `ADMIN` 세션만** 받는다 (D-09).
2. **행위와 활동 로그를 한 트랜잭션에 쓴다** — 기록 없는 운영자 행위가 생기지 않게 (3.3 규칙 5). 대상은 종류·id·표시 이름을 함께 남긴다 (4.14).

### 6.17 계정 · 가입

#### A-01 운영자 로그인

| 칸 | 내용 |
| --- | --- |
| 처리 | 이메일·비밀번호를 확인한 뒤 **2FA 를 한 단계 더** 받는다 — 목업 로그인 화면에는 이 단계가 없다 (D-09 · O-44). 방식 O-33, 실패 잠금 O-35. IP 제한은 dev-plan 3.4 가 이유로만 들었다 — 도입 여부는 10장 |
| 결과 | `ADMIN` 세션. **로그인도 활동 로그에 남긴다** — "접속 기록은 감사 로그에 저장됩니다" ([목업 Admin][mk-admin]) |

#### A-02 초대 발급

| 칸 | 내용 |
| --- | --- |
| 입력 · 주최사 | 상호 · 사업자등록번호 · 대표자명 · 사업장 주소 · 담당자명 · 연락처 · **계정 이메일** · 계약 시작일·종료일 · 이미지 사용 범위 · 비고 ([목업 Admin][mk-admin] 계정 발급), 그리고 연결할 주최사 — 대신 만들어 둔 프로필이 있으면 그것 (D-01) |
| 입력 · 운영자 | 계정 이메일. 누가 발급할 수 있나는 O-19 |
| 처리 | 한 트랜잭션에 ① 사업자·담당자 정보는 **주최사**에(없으면 프로필을 만든다) ② 계약 기간·이미지 사용 범위·비고는 **동의·계약 기록**에 새 행으로 ③ **초대**(토큰은 해시로 — 4.12). 초대 메일은 커밋 뒤에 보낸다 — 메일 실패가 초대를 되돌리지 않는다 (3.4) |
| 규칙 | 이미지 사용 범위는 **세 항목으로 저장한다**(D-04). 발급 폼의 2택(`서비스 내 노출만`·`마케팅 활용 포함`)과 계약 화면의 3항목이 서로 다르다 → O-75 |
| 재발송 | 새 토큰을 만들고 이전 토큰을 무효로 한다 (제안) |
| 예외 | 계정 이메일이 이미 쓰이면 `409` |

#### A-03 가입 신청 승인 · 반려

| 칸 | 내용 |
| --- | --- |
| 승인 | 한 트랜잭션에 멤버십 `ACTIVE` + **주최사 연결** — 운영자가 기존 프로필 후보(R-42)에서 고르거나, 신청 정보로 새 프로필을 만든다. 둘로 만들면 후기·평점이 쪼개진다 (D-01) |
| 반려 | 멤버십 `REJECTED` + 사유(입력 칸은 O-16) |
| 결과 | 승인·반려 안내 메일(커밋 뒤). ⚠️ 목업의 `승인 완료 · 초대 링크가 발송되었습니다` 는 D-01 과 맞지 않는다 — 신청 때 이미 계정이 생겼으므로 승인은 **활성화 안내**다 → O-76 |
| 예외 | 이미 결정된 신청이면 `409` |

### 6.18 소개팅

#### A-04 검수 승인 · 반려

| 칸 | 내용 |
| --- | --- |
| 입력 | 확인 항목 4개(이미지 저작권 · 초상권 동의 · 문구 과장·허위 없음 · 신청 URL 정상 연결) / 반려 사유 하나(이미지 계약 범위 초과 · 초상권 미확인 · 문구 과장 표현 · 신청 URL 오류) + 상세 사유 ([목업 Admin][mk-admin]) |
| 검증 | 승인은 **넷 다 확인**했을 때만, 반려는 **사유를 골랐을 때만** 받는다 — 목업의 `반려 사유를 선택해주세요`. 개정본이 여전히 `검수 대기`인지 본다 — 주최사가 그사이 새 요청으로 바꿔 끼웠으면 `409` (4.6) |
| 승인 처리 | 한 트랜잭션에 개정본 승인 + **공개본 반영**(신규면 회차를 만들고 등록일을 이 시각으로 — O-26) + 검수 결정. 주최사의 `정보 등록` 동의가 유효하지 않으면 `409` |
| 반려 처리 | 개정본 반려 + 사유. 공개본은 그대로다. **사유는 주최사에게 그대로 전달된다** |
| 커밋 뒤 | 주최사에 검수 결과 메일, 신규 공개면 관심지역 신규 알림·검색 반영 (8장). "승인 시 사용자 화면에 즉시 노출됩니다" |

#### A-05 대신 등록 · 수정 · 모집 상태 · 공개 여부

| 칸 | 내용 |
| --- | --- |
| 입력 | 4.5 의 저장값 전부 — 주최사 등록 폼에 없는 것까지 받는다: **위치 정밀도**(`EXACT`·`STATION`·`DISTRICT`와 역 이름·장소명, [P6-2c][plan]), **분위기·직업군**([P6-2d][plan]), 짧은 제목, 참석자 리스트 링크 |
| 검증 | 신청 URL 필수([P6-2][plan]). **이미지·가격은 비워도 된다** — 가격이 신청 폼 안에만 있는 주최사가 많다(D-06 · [FE 12장][fe10]). 직업군은 자유 입력 원문을 보존하고 건당 상한은 O-03, 회사명·학교명은 운영자가 걸러 넣는다 ([decisions 4.15][dec]). 이미지·참석자 링크는 해당 동의가 있을 때만 |
| 처리 | 개정본을 **자동 승인**(결정자 = 본인)으로 남기고 공개본에 반영한다 — 운영자의 변경도 한 줄 이력으로 모인다 (4.6). 모집 상태·정원은 P-06 과 같은 규칙, 공개 여부는 공개본에 즉시 |
| 커밋 뒤 | 신규 공개면 관심지역 신규 알림 (8장) |
| 예외 | 지난 회차의 모집 재개·정원 변경 `409` (D-07) |

#### A-06 반복 규칙

규칙(요일·시각·주기)과 회차 틀, 시작일·종료일을 만들거나 바꾸거나 끝낸다. 회차는 배치가 **한 건씩 따로** 만든다 (3.4 · 8장). 몇 주 앞까지 만드나, 규칙을 바꾸면 이미 만든 회차는 어떻게 하나는 O-20. 만들어진 회차는 독립 회차다 (4.7).

### 6.19 주최사 · 회원 · 후기

#### A-07 주최사 프로필 · 동의·계약 기록

| 칸 | 내용 |
| --- | --- |
| 프로필 | 단계 ①의 주최사를 만든다 — 이름 · **한 줄 소개(필수, 주최사에게 받아 적는다)** · 인스타그램 · 소개 본문 (4.3 · [dev-plan 4장 #15][plan]). 공개 여부를 바꾼다 (제안) |
| 동의·계약 | 바뀔 때마다 **새 행을 쌓는다** — 고치지 않는다 (4.4). 동의 3항목 · 이미지 사용 범위 3항목 · 계약 기간 · 정산 방식 텍스트 · 비고 · 증빙(O-15) |
| 규칙 | 동의를 줄이면(철회) 이미 공개된 회차·이미지를 어떻게 하나는 O-14 — **정해질 때까지 자동으로 내리지 않는다** |

#### A-08 회원 상태 · 주최사 계정 이메일

| 칸 | 내용 |
| --- | --- |
| 상태 | `정상`·`정지`·`탈퇴` — **다음 요청부터 막힌다**(O-32). 목업: "상태 변경은 즉시 적용되며 활동 로그에 기록됩니다". 정지 사유·기간은 목업에 없다 → O-74. 자기 계정은 정지·탈퇴시킬 수 없다 (제안). 주최사 계정 정지와 그 회차 노출은 O-18, 탈퇴 처리 범위는 O-13 |
| 이메일 | 주최사 계정의 로그인 이메일은 **운영자만** 바꾼다 ([목업 ProviderManage][mk-provm]). 중복이면 `409` |

#### A-09 후기 보류 · 삭제 (직권) · A-10 신고 처리

| 칸 | 내용 |
| --- | --- |
| A-09 | 신고 없이도 후기를 `보류`·`삭제`한다 — 참여하지 않은 사람이 본 개인정보 노출 같은 틈을 메운다 (D-05). 한 트랜잭션에 후기 상태 + **평점 집계 증감** (보류가 집계에서 빠지는가 O-09) |
| A-10 입력 | 처리 상태(`접수`·`검토중`·`보류`·`삭제`·`기각`), 처리 메모 |
| A-10 처리 | 한 트랜잭션에 신고 건 상태 + 메모 + (결과에 따라) 후기 상태·평점 집계 (4.14). **메모는 회원에게 보이지 않는다** |
| 커밋 뒤 | 신고자와 작성자에게 결과를 안내한다 — 목업은 "변경 시"라고 적었다. 어느 변경에서, 어느 채널로 보내나는 8장 |
| 미결 | `보류`의 뜻(O-09), 권리침해 신고의 임시조치(정보통신망법 제44조의2)와의 관계(O-47), 종결 뒤 재신고(O-10) |
