# MeetMap 백엔드 기능정의서

**서버가 무엇을 책임지는가**를 정의한다. 화면이 어떻게 생겼는지는 여기서 다루지 않는다 — 그건 [프론트 기능정의서][fe00]가 원본이다.

> **읽는 법.** 전부 읽지 않는다. 작업할 유스케이스의 6장 파일 하나 + `04` 도메인 모델 + `05` 권한이면 대개 충분하다.
> 용어가 걸리면 `02`, 정해지지 않은 것은 `11` 을 본다.

## 전제

| 항목 | 값 |
| --- | --- |
| 코드 | `backend/meetmap` — Spring Boot 3.5.14 · Java 17 · Spring Data JPA · MariaDB · Lombok |
| API 문서 | springdoc-openapi 2.8.17 — Swagger UI `/docs`, OpenAPI `/api-docs` (`application.properties`) |
| 포트 | 8060 |
| 현재 상태 | `MeetmapApplication` 하나뿐인 **스켈레톤**. 실 API 가 없다 |
| 짝 | 프론트는 Next.js 16 이고, 백엔드가 없는 동안 **목 API 로 먼저 만들어졌다** — 그동안의 계약 가안은 [`endpoints.ts`][ep] 가 들고 있다 ([decisions 4.3][dec]). 확정은 이 문서와 springdoc 이 한다 |

## 원본 관계 — 영역별로 나눈다

> 2026-09-11 제안 — **사용자 확인 대기.** 확정되면 11장 결정 이력에 올린다. 그전까지 "FE 우선"을 규칙으로 두지 않은 이유: 백엔드가 비어 있던 동안의 임시 규칙이었고, FE 문서도 스스로 계약을 가안이라 적었다.

| 영역 | 원본 | 이 문서가 하는 일 |
| --- | --- | --- |
| 화면 사양 · 표시 규칙 | [FE `spec/`][fe00] | 인용한다 |
| 제품 정책 값 — 평점 임계·산식 상수·시간대·규모 경계·약관 항목·결제 비대행 | **사용자 결정.** 지금은 FE 문서에 적혀 있다 | 인용한다. 바꿔야 하면 어느 문서가 이기느냐가 아니라 사용자에게 묻는다 |
| API 계약 — 경로·메서드·요청/응답 모양·오류 | **이 문서 + springdoc** | FE 가 적은 요구를 요구사항으로 받아 확정한다. [`endpoints.ts`][ep]·FE 13장은 백엔드가 없던 동안의 가안이다 — 13장 머리말 "실제 스펙 확정 후 갱신", [decisions 4.28][dec] "사실상 백엔드 API 설계 결정" |
| 도메인 · 저장 모델 — 엔티티·상태·이력·삭제 | **이 문서** | FE 12장은 화면이 받는 모양이다 (4.1) |
| 판단 근거 | [FE `decisions.md`][dec] | 번호로 인용한다 (`decisions 4.20`) |
| 성장 단계 · 역할 모델 초안 | [FE `dev-plan.md`][plan] | 이 문서가 2026-09-11 에 일부를 바꿨다 → [11장 결정 이력](11-미결.md#결정-이력) |
| Admin·Provider 쓰기 경로 | [FE `mockups/`][mk] | 도메인 필드가 FE spec 과 어긋나면 FE spec 이 이긴다 (D-06) |

⚠️ **API 계약·도메인 모델을 FE 문서와 다르게 정할 때도 먼저 묻는다** — 프론트의 목·타입 수정이 따라오기 때문이다. 묻는 상대는 FE 문서가 아니라 사용자다. 합의되면 FE 쪽 할 일을 [11장 `프론트 사양 · 목업 갱신 대기`](11-미결.md) 에 모으고, 프론트 문서는 사양 갱신 판에서 고친다.

## 작성 규약

| 규약 | 내용 |
| --- | --- |
| **스키마를 쓰지 않는다** | 엔드포인트는 메서드·경로·책임만 적는다. 필드 목록·예시 JSON 은 springdoc 에 위임한다 — 두 곳에 쓰면 반드시 어긋난다 |
| **출처를 붙인다** | 판단마다 링크 — `[FE 7.4]` `[decisions 4.20]` `[dev-plan 3.3]` `[목업 Provider]`. FE 는 **장 번호**로 적는다(파일은 FE 00-index 표로 찾는다) |
| **출처의 범위를 적는다** | 한 칸에 출처가 있는 말과 백엔드의 해석이 섞이면, 해석 쪽에 `제안` 을 붙이고 근거 칸에는 `앞 문장만 [FE 12장]` 처럼 출처가 걸리는 범위를 적는다 — FE 가 정하지 않은 것을 FE 출처로 묶지 않는다 |
| **추정하지 않는다** | 근거 없는 정책·산식은 `TBD(O-xx)` 로 두고 11장에 모은다. 프론트에 값이 있으면 그 값을 그대로 쓴다 |
| **설계 판단은 `제안`** | 모듈·트랜잭션·저장 방식처럼 문서가 정하지 않은 구현 판단은 `제안` 이라 적는다 — 정책과 섞이지 않게 |
| **결정은 `D-xx`** | 이 문서를 쓰며 사용자와 확정한 것. [11장 결정 이력](11-미결.md#결정-이력) 이 원본이다 |
| **가안 경로** | FE 에 없는 새 경로(주최사·운영자 API)는 `가안` 이라 적는다 |
