서식은 [6.0](06a-기능-읽기-공개.md), 트랜잭션 경계는 [3.4](03-서비스-경계.md) 를 따른다. **쓰기는 모두 멱등하게 설계한다** (제안) — 프론트가 낙관적 업데이트로 화면을 먼저 그리므로, 재시도·중복 클릭이 상태를 뒤집으면 안 된다 ([decisions 4.59][dec]).

### 6.9 인증 · 온보딩

#### W-01 소셜 로그인 · 첫 가입

| 칸 | 내용 |
| --- | --- |
| 입력 | 소셜 종류(카카오·네이버·구글), 로그인 뒤 돌아갈 앱 경로 |
| 검증 | 돌아갈 경로는 **같은 오리진의 경로만** 받는다 — 첫 글자가 `/` 이고 둘째가 `/`·`\` 가 아니며 제어문자가 없고 512자 이하 (제안 — FE `safeRedirect` 와 같은 규칙을 서버도 적용한다, [decisions 4.45][dec]) |
| 처리 | 1. 목적(`USER 로그인`)과 돌아갈 경로를 **서명한 `state`** 에 싣고 소셜 인증 주소를 돌려준다 ([dev-plan 3.3][plan])<br>2. 콜백에서 `state` 서명·만료를 검증하고, 인가 코드를 소셜 신원으로 바꾼다 — **트랜잭션 밖에서** (3.4)<br>3. 그 신원이 묶인 계정이 없으면 한 트랜잭션에 계정 + 로그인 수단 + USER 멤버십(`ACTIVE`)을 만든다<br>4. 신원이 **USER 가 아닌 계정**(주최사 계정에 연동된 소셜)에 묶여 있으면 거절한다 (5.2 규칙 3)<br>5. 토큰을 발급해 **브라우저 응답**에 쿠키로 심는다 — 콜백은 브라우저가 직접 타므로 쿠키가 전달된다 ([decisions 4.50][dec])<br>6. 프론트의 착지 경로 하나로 보낸다. 신규는 약관, 기존은 돌아갈 경로 — 이 판정은 **프론트 `signInLanding` 한 곳**이 한다 ([decisions 4.45][dec]) → O-72 |
| 결과 | 로그인 세션. `isNewUser` 는 필수 약관 동의 이력이 없으면 참이다 (4.11) |
| 예외 | 서명·만료 불일치, 소셜 인증 실패, 역할 불일치, 정지·탈퇴 계정 → 프론트 `/onboarding?error=<코드>` 로 보낸다. 토스트는 프론트가 띄운다 ([decisions 4.46][dec]). 탈퇴한 신원의 재가입은 O-13 |

#### W-02 로그아웃

토큰을 무효화하고 쿠키를 지운다. 이미 무효인 토큰으로 불러도 성공으로 답한다 (멱등, 제안).

#### W-03 약관 동의

| 칸 | 내용 |
| --- | --- |
| 입력 | 네 항목의 동의 여부 — 만 19세 이상 · 이용약관 · 개인정보(필수), 마케팅(선택) ([FE 3.2][fe03]) |
| 검증 | 필수 셋 중 하나라도 거짓이면 `400` |
| 처리 | 1. 약관 동의 이력을 **한 행 더 쌓는다**(버전 O-54). 이미 동의한 사람이 다시 내도 새 행이다 — 퍼널 중간을 새로고침하면 다시 낼 수 있다 ([decisions 4.45][dec])<br>2. 마케팅 동의를 알림 설정에 반영하는 규칙은 O-22<br>3. `isNewUser` 가 거짓이 된 **갱신 토큰을 응답 본문으로** 돌려준다 (제안) — 이 호출은 프론트 서버 액션에서 나가는 서버→서버 요청이라 `Set-Cookie` 가 브라우저까지 못 간다. [`endpoints.ts`][ep] 가 적은 두 선택지 중 "서버 액션 구조에 단순한" 쪽이다 → O-69 |
| 근거 | [FE 3.2][fe03] · [decisions 4.43·4.50][dec] |

#### W-04 프로필 저장 · W-05 선호 지역

| 칸 | 내용 |
| --- | --- |
| W-04 입력 | 닉네임 · 출생연도 · 성별 · 선호 지역 ([FE 3.4][fe03]) |
| W-04 검증 | 닉네임은 앞뒤 공백을 버리고 1~12자(중복 O-53), 출생연도 1975~2007, 성별 `F`·`M`, 선호 지역은 마스터 8곳 안에서 중복 없이 3개 이하. 어기면 `400` (제안) — 프론트가 이미 정규화하므로 서버에 오는 위반은 클라이언트 결함이다 |
| W-04 처리 | 프로필을 만들거나 바꾸고, **선호 지역을 통째로 덮어쓴다.** 이 저장으로 인증 주체 축(가격·자격)이 열린다 ([decisions 4.44][dec]) |
| W-05 처리 | 선호 지역**만** 바꾼다. **프로필이 없는 계정에도 받는다** — 위치 권한 화면은 프로필을 건너뛴 사람에게도 지역을 묻는다. 그래도 `GET /users/me/profile` 은 닉네임·성별이 생길 때까지 `404` 다 (R-21) |
| 근거 | [`endpoints.ts`][ep] `user.preferredAreas` 요구사항 셋 · [decisions 4.53][dec] |

### 6.10 찜 · 알림

#### W-06 찜 설정 · 해제

| 칸 | 내용 |
| --- | --- |
| 처리 | `PUT` 이 찜, `DELETE` 가 해제다 — **원하는 결과 상태**를 받는다. 이미 그 상태면 아무것도 바꾸지 않고 성공한다. 찜 한 행만 바꾸고, 찜 수 통계는 커밋 뒤에 반영한다 (3.4) |
| 규칙 | 지난 회차·마감 회차도 찜할 수 있다 (제안) — 상세는 지난 회차도 열리고(D-08) 찜 목록은 끝난 회차를 남긴다 |
| 예외 | `PUT` 의 대상이 없거나 노출 불가면 `404`. `DELETE` 는 대상이 없어도 성공한다 |
| 근거 | [decisions 4.59][dec] · [`endpoints.ts`][ep] `user.like`. FE 13장의 `POST` 는 FE 16장이 이미 갱신 대기로 올렸다 |

#### W-07 알림 읽음 · W-08 알림 설정

| 칸 | 내용 |
| --- | --- |
| W-07 | 한 건 또는 전부를 읽음으로. 이미 읽었으면 그대로 성공. 남의 알림은 `404` |
| W-08 | 네 항목을 **통째로** 저장한다. 방해 금지 시간은 `OFF`·`23_08`·`00_09` 만. 프론트는 토글마다 즉시 저장하고 실패하면 되돌린다 ([FE 10.3][fe08]) — 그래서 멱등한 `PUT` 이다 |

### 6.11 후기 · 신고 · 이동 기록 · 탈퇴

#### W-09 후기 작성

| 칸 | 내용 |
| --- | --- |
| 선행조건 | 그 회차에 **참여 인증**이 있다 — 방식이 정해지지 않았다(O-01). **정해지기 전에는 이 엔드포인트를 열지 않는다** ([dev-plan Phase 5][plan] 선행 조건) |
| 입력 | 별점 1~5, 본문, 태그(선택) |
| 검증 | 본문은 앞뒤 공백을 뺀 10~500자(세는 단위 O-70), 태그는 후기 태그 마스터 9종 안에서. 이미 쓴 회차면 `409` — 참여한 회차당 1건이다 (4.8) |
| 처리 | 한 트랜잭션에 후기 + 태그 + **주최사 평점 집계 증분**. 주최사는 **회차에서 붙인다** — 요청에 주최사 값이 와도 쓰지 않는다 ([FE 13장][fe11]) |
| 결과 | 저장된 후기. 주최사 소개 페이지에 공개된다 — 작성 화면이 이것을 고지한다 ([FE 10.5][fe08]) |

#### W-10 후기 신고 (USER)

| 칸 | 내용 |
| --- | --- |
| 선행조건 | 그 후기가 달린 회차에 참여 인증이 있다 (D-05 · O-01). 자기 후기는 신고할 수 없다 (제안) |
| 입력 | 사유(특정인 비방 · 허위 사실 · 개인정보 노출 · 광고성 게시물), 내용 |
| 처리 | 한 트랜잭션에 신고 + 신고 건(열린 건이 있으면 거기에 쌓고, 없으면 연다 — 종결 뒤 재신고는 O-10). **후기는 숨기지 않는다** — 숨김·삭제는 운영자 처리로만 생긴다 (D-05) |
| 예외 | 같은 후기를 두 번 신고하면 `409` (4.14) |

#### W-11 신청 URL 이동 기록

| 칸 | 내용 |
| --- | --- |
| 처리 | (회차, 계정 — 게스트면 없음, 시각) 한 행을 **단독 트랜잭션**으로 남긴다. 마감·지난 회차도 받는다 — 이동을 막지 않는다 (D-07). 같은 사람의 반복 이동을 몇 번으로 셀지는 O-05 와 함께 정한다 |
| 예외 | 없는 회차 `404`. 프론트는 이 호출의 실패로 사용자의 이동을 막지 않는다 ([FE 7.3][fe06] · [`endpoints.ts`][ep]) |
| 근거 | 결제가 붙으면 **이 경로의 뒤만** 바뀐다 — 외부 이동 기록 → 내부 주문 (3.5) |

#### W-12 탈퇴

본인이 탈퇴한다. 계정을 `탈퇴`로 바꾸고 세션을 끊는다. 개인정보 파기·익명화 범위와 재가입 규칙은 O-13·O-46 — **정해질 때까지 처리 범위를 적지 않는다.** 탈퇴 화면도 아직 없다 ([FE 16장][fe14]).
