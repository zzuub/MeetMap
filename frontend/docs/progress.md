## 0. 갱신 규칙

**기능을 추가하는 PR 은 이 문서도 같은 PR 안에서 갱신한다.** 나중에 몰아서 쓰면 "왜 그렇게 했는지"가 이미 사라진 뒤다.

| 무엇을 | 어디에 |
| --- | --- |
| 완료한 작업 ID (P0-1 등) | 2장 진행 현황 표의 상태를 갱신 |
| PR 단위 작업 내용 | 3장 맨 위에 새 항목 추가 (최신순) |
| **되돌리기 어려운 판단** | [decisions.md](decisions.md) 맨 아래에 추가 — 대안·근거·번복 조건까지 |
| 미룬 것 / 막힌 것 | 5장에 추가하거나, 해소되면 제거 |

`decisions.md` 가 이 기록의 핵심이다. 코드는 *무엇을* 했는지 보여주지만 *왜* 는 보여주지 않는다. 3개월 뒤 "이거 왜 이렇게 돼 있지"에 답하는 게 그 문서다.

**3장은 이력 8건을 넘기지 않는다.** 9건째를 쓸 때 가장 오래된 것부터 [progress-archive.md](progress-archive.md) 3장 맨 위로 내린다 — 내용은 그대로 옮기고 지우지 않는다. 이 문서는 **세션마다 읽히므로** 길이가 곧 비용이다. "길어지면 내린다"로 뒀더니 4일 만에 12건이 쌓여 2.75배가 됐다.

같은 이유로 **3장 항목은 왜가 아니라 무엇을 적는다.** 근거·대안·번복 조건은 `decisions.md` 가 원본이고 여기서는 번호로 가리킨다.

기록할 가치가 없는 것: 오타 수정, 포맷팅, 자명한 리팩터링.

## 3. 작업 이력

### 2026-09-08 · [#23](https://github.com/zzuub/MeetMap/issues/23) · P1-8
**외부 신청 이동 모달 — 그리고 마감 회차를 막지 않기로 한 것**

`features/event-apply` 를 신설했다. **버튼과 모달이 한 덩어리로 나간다** — 화면이 모달을 직접 열게 두면 모달 없이 버튼만 놓는 자리가 생기고 그게 7.3 을 우회하는 경로다. P3-2 마커 시트의 신청 버튼도 이 슬라이스를 거친다.

**하단 고정 CTA 는 `신청하기` 하나로 세우고 찜·비교 자리는 슬롯으로 비웠다** → 4.36. 4.16 이 카드에 쓴 것과 같은 형태이고, 이름(`features/event-apply`)도 거기서 이미 지목해 뒀던 것이다. **슬롯은 비면 DOM 에 아무것도 없어서** `누르면 아무 일 없는 컨트롤은 만들지 않는다` 와 부딪히지 않는다 — 비활성 버튼·빈 칸을 세우는 것과 갈리는 지점이 여기다. 7.2 의 `flex 1.4` 는 셋이 다 설 때의 값이라 지금은 `flex-1` 이다.

**7.3 의 TBD 를 닫았다** → 4.37. 마감 회차(`status === '마감'`)의 `신청하기` 는 **막지 않고** 모달이 고지를 한 줄 더 얹는다. 근거 셋 — ① 주최사가 임의 시점에 마감을 선언하므로 운영자가 옮겨 적은 `status` 는 태생적으로 늦다 ② 7.3 의 하단 경고 자체가 자격 미달자를 통과시키고 결과만 알리는 설계다(판정 주체가 주최사다) ③ 막으면 성장 단계 ①에서 주최사에 줄 수 있는 유일한 값인 유입이 끊긴다. 2.5 의 비활성 라벨 패턴은 **사용자가 풀 수 있는** 미충족 사유용이라 마감에는 안 맞는다. `spec/06` 도 함께 고쳤다.

- **`확인하고 이동` 은 버튼이 아니라 `<a>` 다.** 로깅을 `await` 한 뒤 `window.open` 을 부르면 사용자 제스처와의 연결이 끊겨 **팝업 차단에 걸린다.** 앵커면 브라우저가 탭을 직접 열어 `logOutboundClick` 의 성패와 무관하게 이동이 보장된다 — `ports.ts` 의 "실패해도 흐름을 막지 않는다" 계약을 코드 모양으로 지킨 것이다
- **필수 문구를 `model/copy.ts` 로 모으고 테스트로 잠갔다.** jsdom 이 없어(4.10) 모달이 실제로 그리는지는 못 보지만, 실무에서 일어나는 쪽은 "고지를 지웠다"가 아니라 **"짧게 다듬었다"** 다. `REQUIRED_PHRASES` 가 `Record<OutboundCopyKey, …>` 라 문구를 더하면 필수 여부 판단이 컴파일 에러로 강제된다
- **CTA 바는 포털하지 않는다.** 4.8 의 함정은 **조상의** `transform`/`backdrop-filter` 인데 `(stack)` 셸에는 둘 다 없고, 이 바는 딤·포커스 트랩을 갖는 오버레이가 아니라 상시 노출 크롬이다. 모달은 자기가 `document.body` 로 포털해 이 위(z-50 > z-40)에 뜬다
- 본문 하단 여백을 `pb-10` → `pb-[calc(var(--height-fixed-cta)+16px)]` 로 바꿨다. 이 값이 조건부가 되는 것은 P3-4 의 몫이다 (4.32 ⚠️)
- `decisions.md` 의 `(PR #28 리뷰)` 를 `#29` 로 고쳤다 — #28 은 PR 이 아니라 이슈다

검증: `tsc`·`eslint`·`vitest 283건`(신규 15건)·`next build` 통과. 변이 3종 — 법적 고지 축약 / 필수 구절 검사 비우기 / 문구 추가 후 표 미갱신 — 이 각각 테스트 실패·컴파일 에러로 잡혔다. 브라우저로 모달 필수 4요소·포커스 트랩·배경 스크롤 잠금·Esc·딤 클릭·`rel="noopener noreferrer"`·마감 고지(`evt-007`)·가격 미확인(`evt-004` → `링크 확인`)을 확인했고, 84px 바가 본문 마지막 줄을 가리지 않는 것도 좌표로 봤다.


### 2026-09-08 · [#22](https://github.com/zzuub/MeetMap/issues/22) · P1-7
**소개팅 상세 — 그리고 하단 CTA 를 이번에 만들지 않기로 한 것**

`EventCard` 의 기본 `href` 는 `/events/{id}` 인데 **그 라우트가 없었다.** 홈·탐색·디자인 시스템의 모든 카드가 404 로 가고 있었고, 이번에 그게 닫혔다.

착수 전에 **컨트롤 셋을 먼저 정했다** → 4.32. 주최사 블록의 `소개 보기 >`·메타 줄 주최사명(P5-4)과 하단 고정 CTA 3종(찜 P2-7 / 비교 담기 P3-4 / 신청하기 P1-8)이 **전부 다른 단계**라, 붙이면 이번 화면에서 눌러서 무언가 일어나는 컨트롤이 하나도 없다. 4.29 가 뷰 토글에 쓴 기준을 그대로 적용했다.

- ⚠️ **`/providers/[id]` 는 자리표시자가 아니라 404 였다.** "지금 누르면 자리표시자로 간다"고 알고 시작했는데 `src/app` 에 `providers` 라우트가 **아예 없다.** 4.29 의 `?view=map` 은 홈 프로모 카드로 이미 도달 가능해 자리표시자가 있었지만 이쪽은 진입점이 없어 만든 적이 없다
- ⚠️ **주최사 링크는 한 자리가 아니라 둘이다.** 7.1 이 `소개 보기 >` 를 "유일한 진입점"이라 쓰지만 같은 표의 **메타 행이 주최사명도 링크로 지정**한다. "유일한 진입점"은 화면 단위의 말이다
- **`신청하기` 를 `externalApplyUrl` 로 직결하지 않았다.** 결제 비대행 고지(7.3)를 우회하는 경로가 된다 — `P1-8 은 타협 불가` 의 첫 문장이 그것이다. **바는 P1-8 이 모달과 함께 세운다** (어차피 한 번만 만들어지므로 미루는 비용이 0)
- **CTA 가 없으니 하단 여백에 84px 를 비우지 않는다.** 없는 바를 위해 비우면 화면 아래가 이유 없이 빈다

**`참석자 정보` 행은 집계값을 다시 쓰지 않는다** → 4.33. 7.1 이 그 행에 적은 세 값(출생연도 범위·직업군·남녀 정원)은 **정보 카드가 이미 쓰는 값과 같다.** 그대로 옮기면 한 화면에 `남 7 · 여 7` 이 두 번 찍힌다. 그 행은 표시 항목이 아니라 **7.2 원칙의 요약**으로 읽고, 블록으로는 7.2 가 유일하게 더하는 것 — 동의한 주최사의 원본 리스트 아웃링크 — 만 남겼다. 동의가 없으면 블록이 통째로 없다(목 8건 중 `evt-007` 하나만 있다).

리뷰는 `console.warn` 의 자리·서버 전용·프로덕션 잔존을 "전부 의도한 대로"로 봤고(`removeConsole` 설정이 없어 스트립되지 않는 것까지 확인해 줬다), `aria-current` 생략도 명세상 안전하다고 답했다. 짚은 것은 둘이다.

- **로그가 어느 축인지 말하지 않았다.** 두 스캔이 같은 문자열을 찍어, 보는 사람이 "지역 건수가 죽었다"와 "시간대 건수가 죽었다"를 구분할 수 없었다. `scan(axis, query)` 로 축 이름을 넣었다
- **`null` 일 때 선택된 구의 `0곳` 이 사라졌다.** #25 1차 리뷰에서 "원인을 보여주는 최소 단위 정보"라고 정당화한 그 표시가, 정확히 스캔이 커져 `null` 이 뜨는 순간 — 즉 **그 정보가 가장 필요해지는 순간** — 함께 꺼졌다. **선택된 구의 건수는 화면 결과 수와 같으므로**(목록이 이미 그 구로 걸러져 있다) 스캔과 무관하게 정확히 안다. 그 값을 쓰도록 고쳤다

**리뷰가 새로 발견한 구조적 사실 하나** → 4.28 에 적었다. 각 축의 스캔 크기는 *자기 축만 지운* 조건의 건수라, 구를 좁혀도 지역 스캔은 안 좁아진다 — **지역 축이 항상 먼저 죽는다.** 한쪽만 `null` 인 상태가 비정상이 아니라 정상이라는 뜻이고, 축을 구분하는 로그가 필요한 이유도 여기 있다.

검증: `tsc`·`eslint`·`vitest 215건`·`next build` 통과. `SCAN_LIMIT` 을 3으로 낮춰 퇴화 경로를 실제로 밟았다 — 구 26행이 건수 없이 전부 뜨는 가운데 **선택된 `송파구 0곳` 만 살아남고**, 로그가 `[explore] 시간대 …` / `[explore] 지역 …` 으로 갈려 서로 다른 건수(8건/5건)를 찍는 것을 확인했다. 상한을 되돌린 뒤 정상 경로도 다시 확인했다.

### 2026-09-05 · [#20](https://github.com/zzuub/MeetMap/issues/20) · [PR #25](https://github.com/zzuub/MeetMap/pull/25)
**코드리뷰 반영 — 갈아탈 시점을 알려주는 신호에 관측 지점이 없었다**

리뷰는 네 질문에 "지금 선택이 맞다"로 답했고, **실질적 결함은 하나**를 짚었다. 4.28 이 스스로 "`null` 이 뜨기 시작하는 것이 서버 패싯으로 갈아탈 신호"라고 못박아 놓고 **그 신호를 관측하는 코드가 어디에도 없었다.** 화면은 고장 나지 않고 "전부 노출 + 건수 없음"으로 조용히 굳기 때문에, 이대로면 사용자 문의로만 알게 된다.

- **`scan()` 에 `console.warn`** — 상한을 넘기면 총 건수와 상한을 남긴다. 리포 전체에서 첫 `console` 사용이라 의도를 주석으로 붙였다. 관측 도구가 생기면 이 자리를 바꾼다
- **4.28 에 축 확장 규칙 한 줄** — "건수 UI 가 붙는 축마다 스캔이 하나씩 는다". 분위기·`area` 에 건수를 붙이는 사람이 이 PR 의 논의를 다시 찾지 않아도 되게
- **`RegionSheet` 에 ARIA 근거 주석** — 이 목록은 **누르면 조건을 바꾸고 닫는 탐색형 액션**이라 `aria-current` 다(`bottom-nav` 와 같은 이유). `Chip`(`aria-pressed`)·`SegmentedControl`(`radiogroup`)로 "고쳐버리는" 것을 막는다. 비선택 항목은 속성을 빼서 `bottom-nav` 와 형태도 맞췄다

**받지 않은 것 — 스캔 중복 제거.** 지역·시간대 둘 다 안 걸린 기본 상태에서는 두 스캔의 조건이 같아 한 번으로 줄일 수 있다. 그런데 그 분기가 **조회를 쏘는 층**에 생기는데 거기는 fetch 목이 없어 테스트가 안 닿고, 필터가 하나라도 걸리면 다시 두 번이라 근본 해결도 아니다. 대신 리뷰가 짚은 **"지금도 표시 6건에 스캔 최대 600건"** 이라는 비용을 5장에 미래형이 아니라 현재형으로 다시 적었다.

검증: `tsc`·`eslint`·`vitest 215건`·`next build` 통과. 로깅 경로는 목 8건으로는 밟히지 않아(상한 300) `itemsOrNull` 단위 테스트로만 덮인다.

### 2026-09-05 · [#20](https://github.com/zzuub/MeetMap/issues/20) · [PR #25](https://github.com/zzuub/MeetMap/pull/25) · P1-5b
**지역 선택 시트와 상단 지역 버튼**

6.3 의 시/도 → 구 2단 시트를 만들고, 그 진입점인 상단 지역 버튼(`📍 서울 전지역 ▾`)을 붙였다. 착수 전에 막아 뒀던 **구별 건수 기준**을 먼저 정하고 시작했다 → 4.28.

- **`api/exploreFacets.ts`** — `slotCounts.ts` 를 대체한다. 시간대·구 건수를 **스캔 2회**로 함께 만든다(전에는 슬롯만 4회, 구까지 오면 25회였다). **자기 축만 푼다** — 시간대 집계는 `slot` 만, 지역 집계는 `district` 만 풀어야 두 축이 서로를 본다
- **`ui/RegionSheet.tsx`** — 1단 시/도(서울만 활성, 나머지 `오픈 예정` + `disabled`) / 2단 구(`서울 전지역` + 소개팅이 있는 구만 + `N곳`). **고르면 닫는다** — 확정 버튼이 사양에 없고 단일 선택이라 남아 할 일이 없다
- **`RegionButton`** — 라벨이 `서울 전지역` ↔ `서울 {구}` 로 바뀐다. **지역이 적용 필터 칩 줄에서 빠지는 근거가 이 버튼**이다 (6.2 표시 제외)

**구 건수는 현재 필터를 반영한다** (사용자 확정). `소수정예` 를 걸어둔 사람에게 `강남구 3곳` 을 보여주고 눌렀더니 0건이면 건수가 거짓말이 된다. 같은 화면의 시간대 칩이 이미 그 규칙이라 두 컨트롤이 갈리는 문제도 없앤다.

**못 셌으면 건수를 포기한다.** 스캔 상한을 넘기면 버킷이 조용히 작아져 **있는 구가 목록에서 빠진다.** 그 축은 `null` 로 돌려 전부 노출하고 건수를 감춘다 — 침묵하는 오답보다 "못 셌다"가 낫다.

**0건이 된 선택 구는 목록에 남긴다.** 다른 조건을 좁혀 0건이 됐을 때 항목이 사라지면 걸려 있는 지역을 풀 수 없다(시간대 칩과 같은 이유). 이때 `0곳` 을 그려서 **빈 결과의 이유가 그 줄에서 읽히게** 했다.

검증: `tsc`·`eslint`·`vitest 215건`(신규 13건)·`next build` 통과. 변이 9종 — 시간대 집계가 지역까지 풀기 / 지역 집계가 시간대까지 풀기 / 자기 축을 안 풀기 / 게스트 조건에 인증 축 만들기 / 상한 초과인데 부분 집계 내놓기 / 0건을 못 셈으로 취급 / 슬롯 버킷 0 초기화 생략 / 구 버킷 누적 대신 덮어쓰기 / 원본 조건 변형 — **전부 실패를 확인했다.** 브라우저에서 2단 계층·`오픈 예정` 비활성·구 선택 후 닫힘·필터에 따라 구 목록이 8개 → 5개로 줄어드는 것·`district=MAPO` 일 때 시간대 칩이 `전체/심야` 로 줄어드는 것(축이 서로를 본다)·선택 구가 `0곳` 으로 남는 것을 확인했다.

**조회를 쏘는 `exploreFacets` 자체는 테스트가 없다** — fetch 목이 없어 목 API 를 통째로 갈아끼우는 것 말고는 방법이 없다. 대신 틀리면 화면이 거짓말을 하는 규칙 셋(축 푸는 방식·상한 초과·버킷팅)을 순수 함수로 떼어 덮었다.

### 알려진 기술 부채

- **`cn()` 이 Tailwind 클래스 충돌을 해결하지 않는다** — 문자열 결합만 한다. 컴포넌트 `className` 오버라이드 시 기본값과 겹치지 않는 유틸리티를 넘겨야 한다. 충돌이 실제로 문제되면 `tailwind-merge` 도입 검토. 카드 조각은 이 제약 때문에 타이포를 아예 갖지 않는다 → 4.17
- **터치 타깃 44×44 미달 3건** (15장 기준) — `Chip` 38px / `SegmentedControl` 36px / `Toggle` 30×52px. 전부 P0-3 `shared/ui` 다. `IconButton`(44) 처럼 **시각 크기는 두고 히트 영역만 넓히는** 방식으로 고쳐야 하며, 세 컴포넌트를 손대면 모든 화면의 컨트롤 높이가 바뀌므로 별도 작업으로 뺀다
