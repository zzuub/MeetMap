## 0. 갱신 규칙

**기능을 추가하는 PR 은 이 문서도 같은 PR 안에서 갱신한다.** 나중에 몰아서 쓰면 "왜 그렇게 했는지"가 이미 사라진 뒤다.

| 무엇을 | 어디에 |
| --- | --- |
| 완료한 작업 ID (P0-1 등) | 2장 진행 현황 표의 상태를 갱신 |
| PR 단위 작업 내용 | 3장 맨 위에 새 항목 추가 (최신순) |
| **되돌리기 어려운 판단** | [decisions.md](decisions.md) 맨 아래에 추가 — 대안·근거·번복 조건까지 |
| 미룬 것 / 막힌 것 | 5장에 추가하거나, 해소되면 제거 |

`decisions.md` 가 이 기록의 핵심이다. 코드는 *무엇을* 했는지 보여주지만 *왜* 는 보여주지 않는다. 3개월 뒤 "이거 왜 이렇게 돼 있지"에 답하는 게 그 문서다.

**3장이 길어지면 오래된 항목을 [progress-archive.md](progress-archive.md) 로 내린다.** 이 문서는 세션마다 읽히므로 짧게 유지한다.

기록할 가치가 없는 것: 오타 수정, 포맷팅, 자명한 리팩터링.

## 3. 작업 이력

### 2026-09-07 · 목 데이터 날짜를 상대값으로
**"과거로 밀리면 갱신한다"는 주석이 갱신되지 않았다**

`npm test` 가 CI 에서 빨간 채였다. `조건을 겹쳐 걸면 AND 로 좁힌다` 1건 — P1-6 이 만든 회귀가 아니라 **`main` 에서도 재현**되는 목 데이터 노후다. `MOCK_EVENTS` 는 절대 날짜(`2026-09-04`…)를 쓰는데 `isThisWeek` 는 실행 시각 기준이라, 9/7(월)로 주가 넘어가며 `THIS_WEEK` 집합이 `09-04·05·06`(SMALL 포함) → `09-12·13`(둘 다 STANDARD)으로 갈아엎어졌고 테스트가 쓰는 `{THIS_WEEK + OPEN + SMALL}` 이 0건이 됐다.

**날짜를 미는 대신 기준을 바꿨다** → 4.31. `kstFromThisMonday(일수, 시각)` 의 앵커가 `isThisWeek` 가 보는 것과 **같은 `weekRangeKst`** 라, `이번 주 5건 · 그 이후 3건` 배치가 주석의 약속이 아니라 **구조로 보장된다.** 날짜를 밀었으면 다음 주에 같은 방식으로 또 깨졌다.

- **`mock/dates.ts` 신설** — `schedule(일수, 시각)` 이 `date`·`dateLabel`·`timeLabel` 을 한 순간에서 함께 만든다. `getMockEvents()` 는 주를 키로 캐시하므로 같은 주 안에서는 같은 배열 참조라 4.28 전제가 그대로고, 주가 바뀌면 다시 만들어 복구된다
- **등록일 일수는 전부 음수** — 이번 주 월요일 이전이라야 어느 요일에 돌려도 미래가 되지 않는다. 부호 하나로 "아직 등록되지 않은 소개팅"이 뜬다
- **불변식 2개 추가** — `timeSlot 이 개최 시각과 어긋나지 않는다`(6.2 경계는 시작 시각 기준) / `등록일은 언제 돌려도 과거다`. 날짜에 **계산이 생겼으니** 계산이 틀어지는 경로를 잠근다
- **`두 조각으로 나눈다` 를 5:3 으로 조인다** — 전에는 `> 0` 이라 집합이 통째로 바뀌어도 통과했다. 이제 구조로 보장되므로 정확한 수를 단언할 수 있다

검증: `tsc`·`eslint`·`vitest 229건`(신규 2건) 통과. **요일 7일 × 하루의 양 끝 + 연말·연초·윤일**을 시계 고정으로 돌려 전부 통과했고, CI 의 3개 타임존(`America/Los_Angeles`·`Pacific/Kiritimati`·UTC)에서 주 경계 시각으로도 확인했다. 변이 4종 — 기준을 `now` 로 / 요일 하루 밀기 / KST 오프셋 누락 / 등록일 부호 뒤집기 — 중 셋이 잡혔다. **요일 하루 밀기는 통과하는 것이 맞다**: 문서화된 규칙은 버킷과 시각뿐이고 요일에 기대는 규칙이 없다.

### 2026-09-07 · [#21](https://github.com/zzuub/MeetMap/issues/21) · P1-6
**정렬 5종 — 그리고 뷰 토글을 이번에 만들지 않기로 한 것**

착수 전에 **뷰 토글부터 정했다** → 4.29. 지도는 P3-1 이라 `?view=map` 이 자리표시자로 떨어지는데, 토글은 탐색 상단의 **상시 노출 크롬**이라 들어올 때마다 절반이 지키지 못할 약속을 하고 서 있게 된다. `누르면 아무 일 없는 컨트롤은 만들지 않는다`(5.4 / P1-4)에 정면으로 걸리고, 4.24 가 `지도` 탭을 뺀 근거와 같은 문제다. **미루는 비용이 거의 0** 인 것도 컸다 — `view` 축은 이미 URL 계약에 있고 `SegmentedControl` 도 이미 있다.

- **`model/sortChoices.ts`** — 선택지 5종 + 목적지. **주소는 `exploreHref` 가 만든다** — 여기서 `?sort=` 만 갈아끼우면 `eligibleOnly=0` 이 떨어져 자격 필터가 기본값(ON)으로 되살아난다 (4.25). 칩 줄(`filterChips`)과 같은 모양이다
- **`ui/SortSelect.tsx`** — 결과 수 줄 오른쪽. `useTransition` + `router.replace`
- **`parseSort`** — 게스트의 가격 정렬을 기본값으로 떨어뜨린다 → 4.30

**게스트 게이트를 화면에 두지 않았다.** 옵션을 감추는 것은 `hasViewerAxes` 가 하지만(4.27), **값 자체는 파싱이 막는다.** 화면에서만 감추면 손으로 `?sort=priceDesc` 를 붙인 게스트가 남고, `select` 가 자기 옵션에 없는 값을 받아 **아무것도 선택되지 않은 상태**로 뜬다. 평점 정렬은 게스트에게도 보인다 — 주최사 `ratingScore` 기준이라 인증 주체가 필요 없다 (4.20).

**전환 표시를 같이 붙였다.** 시간대 칩이 이걸 빠뜨려 PR #23 리뷰에 걸렸던 자리다. `select` 는 흐려짐 + `aria-busy` 이고, **고른 값을 전환 중에만 붙잡는다** — `value` 가 URL 을 따라오므로 그러지 않으면 응답 전까지 이전 값으로 되돌아간 것처럼 보인다. `pending` 이 내려가면 저절로 URL 값으로 돌아가 뒤로가기에도 낡은 값이 안 남는다.

**지도 자리표시자의 편도를 닫았다.** `?view=map` 은 홈 프로모 카드(5-6)로 **이미 도달 가능**한데 `page.tsx` 가 조기 반환해 그 화면엔 컨트롤이 하나도 없었다 — 리스트로 돌아갈 화면 내 경로가 없었다. 토글을 안 붙이기로 한 이상 그 출구는 이쪽 몫이라 `리스트로 보기` 링크를 넣었다(걸어둔 조건은 `exploreHref` 로 그대로 들고 간다). P3-1 이 토글을 붙일 때 같이 지운다.

검증: `tsc`·`eslint`·`vitest`(신규 12건) 통과. 변이 4종 — 파싱의 게스트 정렬 게이트 제거 / 게스트에게 가격 옵션 노출 / 주소를 손으로 조립 / `selected` 를 기본값 고정 — **전부 실패를 확인했다.** 브라우저에서 게스트 3종·로그인 5종, `가격 낮은순` 이 **여성 기준가** 오름차순(25,000→55,000)인 것, `eligibleOnly=0`·`slot`·`status` 가 정렬을 바꿔도 살아남는 것, 375px 에서 가로 오버플로가 없는 것, 자리표시자의 `리스트로 보기` 가 조건을 유지하는 것을 확인했다.

### 2026-09-05 · [#20](https://github.com/zzuub/MeetMap/issues/20) · [PR #25](https://github.com/zzuub/MeetMap/pull/25)
**4차 코드리뷰 반영 — 번복 조건이 스냅샷 문제를 덮는 것처럼 읽혔다**

리뷰는 두 질문에 다 "지금이 맞다"로 답했다. `FacetAxis = keyof ExploreFacets` 결합은 `ExploreFacets` 의 목적(스캔되는 축별 건수)과 정확히 겹쳐 과하지 않고 — 어긋나는 건 *스캔을 안 거치는 필드*가 그 타입에 섞이는 순간인데, 그때는 파생 방향을 뒤집기보다 그 필드를 다른 타입에 두는 게 먼저다. 스냅샷 전제를 코드로 굳히지 않은 것도 맞다(재현 수단 없음 · 백엔드 계약 근거 없음 · 목에서 합쳐도 이득 없음).
