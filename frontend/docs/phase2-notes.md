## P2-1~P2-5 요점 — 끝났다 (2026-09-10, #25)

- **백엔드에 OAuth 가 없다. `accountApi` 포트를 세웠다** → 4.43. `eventApi`(4.3)와 같은 형태이고 분기는 `api/accountApi.ts` 마지막 한 줄이다. ⚠️ **`meetmap_mock_role` 에 묶지 않았다** — 그 쿠키의 세션은 `isNewUser` 가 항상 거짓이라 묶는 순간 3.1 의 신규 분기가 죽고, 애초에 개발용 역할 스위치이지 화면이 아니다
- ⚠️ **역할 스위치 쿠키가 로그인 세션을 이긴다.** `document.cookie = "meetmap_mock_role=USER;path=/"` 를 한 번이라도 켜 뒀으면 **퍼널을 눌러볼 수 없다.** 지우고 본다:
  `document.cookie = "meetmap_mock_role=;path=/;max-age=0"`
- ⚠️ **역할 스위치를 켠 채 로그인까지 하면 `찜`·`마이` 가 막힌다.** 스위치가 이기므로 역할이 `PROVIDER`/`ADMIN` 로 판정돼 `roles: ["USER"]` 게이트에 걸려 `/onboarding` 으로 되돌아온다 — 실제로는 USER 로 로그인했는데도. 가격·자격은 영향이 없다(`viewer` 는 `meetmap_mock_user` 에서 따로 읽는다). 이것도 스위치를 지우면 사라진다 (PR #35 리뷰)
- **처음부터 다시 보려면 목 쿠키를 지운다.** 로그인은 `meetmap_mock_session`(계정)·`meetmap_mock_user`(약관·프로필) 두 장을 심고 **둘 다 HttpOnly** 라 콘솔에서 못 지운다 — 개발자도구 → Application → Cookies 에서 지운다. 안 지우면 두 번째 로그인부터 `기존 회원 → 홈` 으로 간다(그게 정상 동작이다)
- **`isNewUser` 를 판정하는 자리는 로그인 액션 하나뿐이다** (`signInLanding`). ⚠️ **`/onboarding` 은 세션을 보고 리다이렉트하지 않는다** — 튕겨내면 퍼널 중간에 뒤로가기로 돌아온 사용자가 갇히고, `기존 회원은 홈으로` 분기를 누를 방법이 사라진다 → 4.45
- **`?redirect=` 를 처음으로 읽는다. 검증은 `safeRedirect` 한 곳**(소비 시점)이다 → 4.45. `proxy.ts` 가 만든 값도 믿지 않는다 — 주소창에 직접 칠 수 있다. **신규 가입자에게는 적용하지 않는다**(3.5 가 퍼널의 끝을 못 박았다)
- **퍼널 가드의 구현은 `(funnel)/_guard.ts` 의 `requireFunnelSession` 하나이고, 부르는 자리는 레이아웃 + 단계 셋이다** — 약관 액션 · 프로필 액션 · **완료 페이지** → 4.49. ⚠️ **레이아웃 재실행은 `<Link>` 소프트 내비게이션에서 보장되지 않는다**(두 번 측정해 답이 달랐다). **판단 기준은 쓰기냐 읽기냐가 아니라 `세션에 딸린 일을 하는가` 다** — 처음에 쓰기만 세어 완료 페이지의 조회를 빠뜨렸다
- **그 세는 일은 이제 `_guard.test.ts` 가 한다** → 4.51. 단계 폴더를 훑어 `requireFunnelSession(` 호출을 요구하고 **`NO_SESSION_STEPS` 에 사유가 적힌 단계만** 통과시킨다. **P2-6 을 폴더에 넣고 아무것도 안 하면 테스트가 깨진다** — 가드를 부르거나, 왜 필요 없는지를 그 목록에 적어야 통과한다
- **`viewer` 를 주입했다** → 4.44. 홈·탐색의 `viewer={null}` 이 풀렸고, 인증 축 게이트가 `isGuest: session === null` → **`hasViewer: viewer !== null`** 로 바뀌었다. 이름을 바꾼 것이 요점이다 — 값만 갈아끼우면 다음 사람이 다시 세션을 넣는다. **상세(7.1)는 여전히 대기열 밖이다** (4.32)
- **네 번째 실패 표면이 생겼다 — 쓰기다** → 4.46. 제출 실패는 화면을 갈아끼우지 않고 **폼 안에서** 코드·시각을 알린다(`FormErrorNotice`). 적용 자리는 **약관 제출·프로필 제출 둘**이고, 3.1 의 인증 실패 토스트는 **만들지 않았다**(실패가 나는 자리가 OAuth 콜백이라 목에 재현 경로가 없다)
- **`(onboarding)` 그룹 경계를 붙였다** → 4.47. 근거는 화면 수가 아니라 **출구**다 — 탭도 헤더도 없는 유일한 셸이라 에러 카드가 `홈으로 가기` 를 직접 준다. `loading.tsx` 는 **퍼널 공통 한 장**, `not-found.tsx` 는 **안 만들었다**
- **입력값은 단계마다 제출한다** → 4.48. 2.4 의 `마지막 단계 일괄 제출` 에서 벗어났다 — 완료 화면에는 제출 버튼이 없고, `나중에 할래요` 가 프로필을 건너뛰며, 3.5 동적 문구가 새로고침을 견뎌야 한다
- **`건너뛴 사용자`를 따로 저장하지 않는다.** `프로필 없음`이 곧 그 상태다 — 완료 화면은 3.5 미선택 문구로, 홈·탐색은 `viewer=null`(가격 남·여 병기 · 자격 축 없음 · 가격 정렬 숨김)로 떨어진다
- ⚠️ **목적지가 없는 링크는 만들지 않았다** (4.29 기준): 3.1 `약관 링크` · 3.2 `자세히 보기` → 둘 다 `/policy/terms` 인데 라우트가 없다. 3.5 `홈으로 이동` 은 이제 **위치 권한 화면을 거친다**(P2-6). ⚠️ 여기 적었던 `AFTER_ONBOARDING 상수 하나를 바꾸면 된다` 는 **틀렸다** — 그 상수는 `signInLanding` 의 폴백이기도 하다 (4.52)

## P2-6 요점 — 끝났다 (2026-09-10, #26)

- **`AFTER_ONBOARDING` 을 바꾸지 않았다** → 4.52. 위(P2-5 요점)에 "상수 하나를 바꾸면 된다"고 적어 뒀는데 **틀렸다**: 읽는 자리가 둘이고 뜻이 다르다. `done` 의 `홈으로 이동`(퍼널의 다음 걸음)과 `signInLanding` 의 폴백(**기존 회원**의 로그인 목적지)이다. 바꿨다면 `?redirect=` 없이 로그인한 기존 회원이 매번 위치 권한 화면을 봤다. ⚠️ **`landing.test.ts` 가 상수끼리 비교하고 있어 못 잡았다** — 지금은 리터럴로 잠근다. 더한 것은 `ONBOARDING_STEPS.location` 이고, `done` 의 **링크만** 그쪽으로 돌렸다
- **`주변` 의 축은 좌표가 아니라 지역이다** → 4.53. `EventListQuery` 에 좌표가 없고 URL 에 좌표를 실을 수 없다. 역지오코딩이 좌표를 `area` **한 개**로 되돌리고, 그 뒤로는 기존 `area` 축만 쓴다 — 요약 카드가 세는 집합과 `주변 소개팅 보기`(`/explore?area=…`)가 여는 집합이 같다. **4.2 의 `/explore?view=map` 으로 보내지 않았다**(자리표시자는 `주변` 을 반영하지 않는다)
- **활동 지역(4.3) = 선호 지역(3.4).** 마스터도 한도도 같다. 3.4 에서 고른 지역이 **미리 선택돼** 뜨고 저장도 같은 필드다. ⚠️ `saveProfile` 로는 못 한다(프로필을 건너뛴 사용자도 여기 온다) → **`userApi.savePreferredAreas`** 좁은 쓰기. 지역만 남고 `getMyProfile` 은 계속 `null` 이라 `viewer` 가 근거 없이 살아나지 않는다 (4.44). ⚠️ **지금 이 값을 읽는 자리는 `onboardingSummary`(3.5) 하나다** — 홈·탐색은 서버 산출값 `baseAreaLabel` 을 보므로 실 API 전환 때 살아난다
- **`entities/geo` 를 세웠다** → 4.54. 역지오코딩 API 가 아예 없었다. **좌표는 서버 액션 안에서만 살고 URL·쿠키·클라이언트 상태 어디에도 안 남는다** — 4.1 고정 문구가 지킬 수 있는 약속이 되도록 남을 수 있는 자리를 표로 세어 막았고, 백엔드 요구사항은 `ENDPOINTS.geo.reverse` 에 적었다. 목의 `label` 은 지역 마스터 라벨(`성수·건대`)이고 행정동까지 내려주는 것은 실 API 몫이다
- **거리순 축을 만들지 않았다** → 4.56. 4.3 의 `거리순 정렬 비활성` 은 **비활성할 대상이 없다.** 6.2 자신이 TBD 이고, 좌표를 URL 에 못 실어 축을 만들면 6.1 계약이 깨진다. 4장 문구 셋(4.1 혜택 ①② · 4.2 `반경 3km` · 4.3 제약 안내)을 지금 참인 문구로 바꿨고 **되돌릴 문구는 `MAP_AXIS_PHRASES` + 양방향 테스트**가 들고 있다 — P3-1 이 `SORT_OPTIONS` 에 `distance` 를 더하는 순간 빨간불이 켜진다
- **3상태는 `LocationPermissionGate` 의 `useState` 하나다** → 4.55. 진입 경로 × 상태 11줄을 표로 먼저 적었다. **권한이 이미 허용돼 있어도 `asking` 에서 시작한다**(누른 적 없는 화면을 보여주지 않는다). `denied` 로 떨어지는 길이 셋(권한 거부 / 측위 실패·타임아웃 / 미지원)이라 사유를 값으로 들고 다니고, **모르는 오류 코드를 `PERMISSION` 으로 읽지 않는다**
- **4.2 의 `권한 요청 화면 다시 보기`(실서비스 TBD)는 `지역 직접 선택할게요` 가 됐다.** 없애면 상태가 일방통행이 되고 그대로 두면 프로토타입 컨트롤이 남는다 — 목적지를 사용자가 실제로 원하는 곳(`denied`)으로 바꾸면 TBD 가 사라진다. 덕분에 **브라우저 권한을 되돌리지 않고도 세 화면에 전부 도달한다. 개발 전용 스위치는 없다**
- **훅은 전부 게이트에 있고 화면 셋은 순수 컴포넌트다** — jsdom 없이(4.10) `renderToStaticMarkup` 으로 문구를 검증하기 위해서다 (4.39 와 같은 형태)

- **정렬은 `다가오는 순 → 지난 순`, 경계는 KST 날짜**(`isPastDayKst`) → 4.65. `편집` 은 그리지 않았다(4.29)
