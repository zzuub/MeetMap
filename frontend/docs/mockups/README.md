# 목업 — `.dc.html`

Claude Design 캔버스(`MeetMap UI/UX 작업` 프로젝트)의 화면 파일이다. 2026-09-10 에 리포지토리로 편입했다 — 그전까지는 캔버스에만 있어서 세션마다 사용자에게 URL 을 물어야 했다.

## 여는 법

`.dc.html` 은 Design Component 형식이다 — 마크업은 인라인 스타일이라 그냥 열어도 그려지지만, `{{ }}` 바인딩과 `<sc-if>` 화면 전환은 같은 폴더의 **`support.js` 런타임이 로드돼야** 풀린다. 런타임 없이 열면 `{{ allMark }}` 같은 자리표시자가 그대로 보이고 한 파일에 든 화면 여러 개가 세로로 쌓여 나온다 (2026-09-10 확인).

⚠️ `support.js` 를 상대경로(`./support.js`)로 물기 때문에 **`.dc.html` 만 다른 데로 옮기면 풀리지 않는다.** 툴에 따라 `file://` 을 data URL 로 바꿔 넣으면서 상대경로가 끊기기도 한다 — 그때도 같은 증상이다.

제대로 보려면 캔버스에서 연다. 편집도 캔버스에서 한다 — 파일만 고치면 캔버스와 어긋나므로, 고쳤으면 캔버스에도 반영하거나 아래 드리프트 표에 적는다.

## ⚠️ 어긋나면 기능정의서가 원본이다

목업이 사양보다 뒤처져 있는 자리가 있다. 판단 기준은 하나다 — **[`../spec/`](../spec/) 이 원본이고 목업은 참고**다 ([spec/00-index.md](../spec/00-index.md)). 특히 `P1-1` 이후 구현된 화면은 **코드가 목업보다 앞서 있다** ([progress.md](../progress.md) 목업 갱신 항목).

## 캔버스로 다시 올리기

**캔버스 (45화면)** — https://claude.ai/code/artifact/d2c9bd0a-b85f-4c48-9f94-4b1f5d118407

`USER` 22 / `ADMIN · PROVIDER` 19 / `공통` 4 세 페이지다. 툴바의 페이지 메뉴로 전환한다.

파일 하나에 화면이 3~5개씩 들어 있어 그대로 올리면 45화면이 12프레임에 숨는다. 그래서 [`build-artboards.mjs`](build-artboards.mjs) 가 **화면당 사본 하나**를 떠서 ① 초기 화면을 고정하고 ② 우하단 플로팅 탭바를 뗀다.

```bash
node build-artboards.mjs      # .build/ 에 45개 + canvas.json
node serve.mjs .build         # http://localhost:4173 로 확인
```

⚠️ **`UserV2` 의 하단 4탭은 떼지 않는다** — 프로토타입 장치가 아니라 제품의 실제 내비게이션이다. `Onboarding` 은 플로팅 탭바가 없고 플로우 버튼으로 넘어간다.

**앞 화면에서 담아야 차는 화면은 상태를 시드한다.** 비교함이 그렇다 — 상세의 `비교 담기` 를 눌러야 표가 차는데 탭바를 떼면 그 경로가 없어서, 시드를 안 주면 빈 상태만 보인다. `build-artboards.mjs` 의 `SEED` 표에 있다.

`.build/` 와 씨앗 산출물(`*.html`, ~4MB)은 `.gitignore` 로 뺐다. 원본 `.dc.html` 12개가 원본이고 나머지는 언제든 다시 만들어진다 — **`.build/` 안의 파일을 고치지 않는다.**

⚠️ 이 캔버스는 `MeetMap UI/UX 작업` **원본 캔버스와 별개다.** 여기서 편집하고 저장하면 원본에는 반영되지 않는다 — 위 드리프트 표를 계속 채워야 하는 이유다.
