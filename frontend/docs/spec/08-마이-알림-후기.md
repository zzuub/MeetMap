## 10. 마이 / 알림 / 후기

### 10.1 마이페이지 — `/my`

| 블록 | 요소 | 동작 |
| --- | --- | --- |
| 프로필 카드 | 아바타, 닉네임, `성별 · 출생연도 · 관심지역`, `수정` | `수정` → `/my/profile/edit` (**목업 없음**) |
| 프로필 완성도 | 진행바 + % + 체크리스트 4항목 (닉네임 등록 / 출생연도·성별 등록 / 선호 지역 등록 / 프로필 사진 등록) | 미완료 항목은 강조색·볼드 |
| 카운터 3종 | 찜한 소개팅 / 신청 이력 / 내 후기 | 각각 해당 목록으로 이동 |
| 후기 작성 유도 배너 | `작성할 후기 N건` + 대상 소개팅명·참여일 | `/reviews/write/[eventId]` |
| 메뉴 그룹 1 | 찜한 소개팅 / 신청 이력 / 내가 쓴 후기 / 비교함 | 각 라우트 |
| 메뉴 그룹 2 | 알림함(안읽음 배지) / 알림 설정 / 약관 및 개인정보 / 로그아웃 | 로그아웃 확인 다이얼로그 필요 (**목업 없음**) |
| 헤더 액션 | `설정` → 알림 설정 | |

- 완성도 계산: `완료 항목 / 전체 항목 × 100`(반올림). 항목 목록은 서버 정의 **TBD**

### 10.2 알림함 — `/my/notifications`

| 기능 | 사양 |
| --- | --- |
| 필터 | `전체 N` / `안읽음 N` 단일 선택 |
| 헤더 액션 | `모두 읽음` |
| 알림 카드 | 종류 아이콘 + 종류 태그 + 상대 시각 + 제목 + 본문 + 안읽음 도트 |
| 안읽음 스타일 | 흰 배경 + 제목 볼드(700) / 읽음은 회색 배경 + 600 |
| 카드 클릭 | 읽음 처리 + **딥링크 이동** (신규→탐색, 후기→후기 작성, 안내→해당 설정) |
| 빈 상태 | `"안읽은 알림이 없어요 / 새 소식이 오면 여기에 표시됩니다"` |
| 페이지네이션 | 목업 미정의 — 무한 스크롤 권장, **TBD** |

**알림 종류(kind)**

| kind | 태그 | 예시 |
| --- | --- | --- |
| `new` | 신규 | 관심지역에 새 소개팅이 등록됐어요 |
| `review` | 후기 | 후기를 작성해주세요 (참여 인증 완료) |
| `info` | 안내 | 알림 설정이 변경되었습니다 |

### 10.3 알림 설정 — `/my/notifications/settings`

| 설정 | 설명 | 기본값 |
| --- | --- | --- |
| 관심지역 신규 소개팅 | 설정한 지역에 새 소개팅이 등록되면 | ON |
| 후기 작성 요청 | 참여 인증 완료 후 후기 작성 안내 | ON |
| 추천 소개팅 소식 | 주 1회, 내 조건에 맞는 소개팅 큐레이션 | OFF |
| 방해 금지 시간 | `사용 안 함` / `23시–08시` / `00시–09시` 단일 선택 | 23시–08시 |

- 상단 고지: `"앱 푸시와 이메일로 함께 발송됩니다"`
- 하단 고지: `"마케팅 정보 수신 동의는 마이페이지 > 약관 및 개인정보에서 변경할 수 있습니다"`
- 토글 변경은 **즉시 저장**(별도 저장 버튼 없음). 실패 시 롤백 + 토스트.
- **마감임박 알림은 삭제됐다.** 잔여 좌석 개념이 없고(선착순이 아님) 신청 마감일도 따로 없어서 발송 조건을 정의할 수 없다. `urgent` 알림 종류와 `deadlineAlert` 설정도 함께 제거한다.

### 10.4 후기 목록 — `/providers/[providerId]/reviews` · `/my/reviews`

| 블록 | 요소 | 주최사 후기 | 내가 쓴 후기 |
| --- | --- | --- | --- |
| 평점 요약 | 평균 평점(세리프 32px), 별 표시, 총 후기 수, **5~1점 분포 막대**(최대값 기준 비율, 4점 이상 진한 색) | ✅ | ❌ |
| 인기 태그 | 참여자가 많이 남긴 태그 Top 5 (`라벨 + 횟수`) | ✅ | ❌ |
| 카테고리 필터 | `전체 / 분위기 / 진행 / 장소` 단일 선택 | ✅ | ✅ |
| 후기 카드 | 아바타, 작성자, `날짜 · 소개팅명`, 별점(★☆), 본문, 태그 칩 | ✅ | ✅ |

> **라우트 분리 완료 (2026-09-02).** 이 화면이 두 용도로 읽힌다는 것이 오랜 미해결 항목이었고, `/events/[id]/reviews` vs `/my/reviews` 로 나누는 안이 올라와 있었다. **평점의 귀속 단위를 주최사로 확정하면서(7.4) 답이 바뀌었다** — 소개팅 회차별 후기 목록은 만들지 않는다. 회차당 후기가 2~4건이라 목록이 성립하지 않고, 평점 요약·분포 막대·인기 태그가 전부 표본 부족으로 무의미해진다.

| 라우트 | 용도 | 진입점 |
| --- | --- | --- |
| `/providers/[providerId]/reviews` | **주최사 후기 목록.** 그 주최사가 진행한 모든 회차의 후기를 모은다 | 주최사 소개 페이지(7.4)의 `후기 전체보기 >` |
| `/my/reviews` | **내가 쓴 후기.** 평점 요약·인기 태그 블록이 없다 — 내 후기 평균은 의미 없는 값이다 | 마이페이지(10.1) 메뉴 · 카운터 |

- 주최사 후기 목록의 후기 카드는 `날짜 · 소개팅명`으로 **어느 회차의 후기인지** 드러낸다. 회차마다 장소·진행이 다르므로 이 정보가 필요하다.
- 후기 5건 미만이면 평점 요약 블록에서 **평균 평점 숫자를 숨기고 분포 막대와 `후기 N건`만** 남긴다 (7.4 임계 규칙).

### 10.5 후기 작성 — `/reviews/write/[eventId]`

| 단계 | 요소 | 검증 |
| --- | --- | --- |
| 대상 소개팅 | 썸네일 + 소개팅명 + `참여일 · 주최사` (읽기 전용) | 참여 인증 완료 건만 진입 가능 |
| 별점 | ★ 5개, 클릭 시 1~5 | **필수** |
| 별점 라벨 | 0 `별점을 선택해주세요` / 1 `아쉬웠어요` / 2 `그저 그랬어요` / 3 `괜찮았어요` / 4 `좋았어요` / 5 `아주 좋았어요` | |
| 태그 | 분위기 3 / 진행 3 / 장소 3, 다중 선택 | 선택 |
| 본문 | textarea, **최소 10자 / 최대 500자**, `N/500자` 카운터 | **필수** |
| 정책 고지 | `"참여 인증이 확인된 소개팅에만 후기를 남길 수 있습니다. 특정인 비방, 개인정보 노출은 삭제될 수 있습니다."` | 필수 노출 |
| 제출 | 별점 > 0 && 본문 ≥ 10자일 때 활성, 라벨이 미충족 사유 안내 | |
| 완료 | `"후기가 등록되었습니다. 감사합니다!"` 인라인 메시지 | 이후 이동 처리 **TBD** |

> **작성 대상은 회차다. 집계 단위만 주최사다** (7.4). 라우트가 `/reviews/write/[eventId]`인 것은 그대로다 — 참여 인증이 회차 단위라 "어느 소개팅에 갔는지"가 확인돼야 후기를 쓸 수 있다. 저장된 후기는 `eventId`와 `providerId`를 함께 갖고(12장), 주최사 페이지의 평점에 합산된다.
>
> 사용자에게 이 사실을 고지한다 — 정책 고지 문구에 **`"작성한 후기는 주최사 소개 페이지에 공개됩니다."`** 를 추가한다. 내가 쓴 한 줄이 어디에 노출되는지 모른 채 쓰게 두지 않는다.

**태그 마스터**

| 그룹 | 태그 |
| --- | --- |
| 분위기 | 분위기 좋아요 / 대화하기 편했어요 / 조용한 편이에요 |
| 진행 | 진행이 매끄러워요 / 시간 관리가 좋아요 / 진행자가 친절해요 |
| 장소 | 접근성이 좋아요 / 공간이 쾌적해요 / 주차가 편해요 |
