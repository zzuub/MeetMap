## ⚠️ 2026-09-01 도메인 재정의 — 목업보다 이 문서가 우선한다

제품 정의가 **"소개팅·미팅 행사 통합 탐색"에서 "인스타그램에 흩어진 로테이션 소개팅 통합 탐색"으로 좁혀졌다.** 그 결과 목업에 그려져 있으나 **실제 도메인에 존재하지 않는 값**이 드러났고, 아래 항목은 목업과 어긋나더라도 이 문서를 따른다.

| 목업에 있는 것 | 실제 | 조치 |
| --- | --- | --- |
| 취미 카테고리(와인/전시/러닝…) | 상품 종류가 **로테이션 소개팅 하나**뿐 | `category` 삭제. 시간대·규모가 대신한다 |
| 잔여 N석 / 마감임박 | 선착순이 아니라 **주최사 심사 선발**. 마감 선언 전까지 계속 받는다 | `remainingSeats` 삭제, 상태를 `신청 가능 / 마감` 2개로 |
| 여성 신청 비율 / 성비 게이지 | 정원이 **남녀 고정(7:7 등)** | `femaleRatio` 삭제 |
| 참가 연령 `N~N세` | 주최사는 **출생연도(`90~96년생`)** 로 모집 | `minAge/maxAge` → `birthYearFrom/To` |
| 단일 가격 | **남녀 가격이 다르다** | `malePrice` / `femalePrice` 분리, 사용자 성별 기준 노출 |
| 신청 마감일 | 별도 마감일이 없다 | `applyDeadline` 삭제, 마감임박 알림 삭제 |

**목업(User v2 / Actions / My)은 아직 이전 정의 기준이다.** 해당 화면 작업 전에 목업 갱신이 필요하다.

## ⚠️ 2026-09-02 평점 귀속 재정의 — 후기는 주최사에 쌓인다

**소개팅 회차에는 평점이 없다.** 사용자가 평점을 보는 시점은 그 회차가 열리기 전이고, 회차는 1회성이므로 신규 회차는 정의상 항상 후기 0건이다. 게다가 정원 7:7 = 14명 중 참여 인증까지 마치고 후기를 쓰는 사람은 회차당 2~4명뿐이라 표본이 성립하지 않는다.

배달 앱의 **가게 리뷰**와 같은 구조로 옮긴다 — 후기는 **회차에 대해 쓰지만 주최사에 쌓인다.**

| 항목 | 조치 |
| --- | --- |
| `EventSummary.rating` · `reviewCount` | **삭제** (12장) |
| `EventSummary.provider: string` | → `{ id, name }` **객체로 승격**. id 없이는 주최사 페이지 링크도 후기 귀속도 불가능하다 |
| 주최사 소개 페이지 | **신설** `/providers/[providerId]` (7.4). 한 줄 소개 · 인스타 아웃링크 · 평점 요약 · 모집 중인 회차 · 후기 목록 |
| 후기 목록 라우트 | `/providers/[id]/reviews`(주최사) + `/my/reviews`(내 후기)로 분리 (10.4). 회차별 후기 목록은 만들지 않는다 |
| 탐색 정렬 | `평점 높은순` 추가 (6.2). 주최사 평점 기준이며 정렬에는 **베이지안 보정값**을 쓴다 |
| 비교함 `후기` 행 | → `주최사 평점` (8장) |
| 카드 5종 | **평점을 그리지 않는다.** 목록 응답이 평점을 나를 이유가 없다 |

근거 전문은 **7.4** 에 있다.
