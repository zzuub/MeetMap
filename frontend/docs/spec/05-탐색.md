## 6. 탐색 — `/explore`

### 6.1 URL 파라미터 설계

```
/explore?view=list|map
        &province=SEOUL
        &district=ALL|GANGNAM|NOWON|DONGDAEMUN|MAPO|SEONGDONG|SONGPA|...
        &when=ALL|THIS_WEEK|LATER
        &slot=ALL|MORNING|AFTERNOON|DINNER|LATE_NIGHT
        &scale=ALL|SMALL|STANDARD|LARGE
        &status=ALL|OPEN
        &maxPrice=30000
        &eligibleOnly=1
        &sort=popular|latest|rating|priceAsc|priceDesc
        &mood=차분한,트렌디한
        &area=성수·건대
```

- `province`는 MVP1에서 `SEOUL` 고정값만 유효하다. 다른 시/도 값은 아직 서버가 데이터를 갖고 있지 않으므로 파라미터 자체는 미리 설계해두되 UI에서 선택 불가 처리한다(6.3 참조).
- `eligibleOnly=1`은 **프로필 기반 자격 필터**다. 로그인 사용자의 `birthYear`가 `birthYearFrom~To`에 들고, 자기 성별 정원이 0이 아닌 건만 남긴다. 게스트에게는 파라미터·토글 모두 노출하지 않는다.
- **`eligibleOnly` 는 3상태로 읽는다 (2026-09-05).** 로그인 사용자 기본이 ON 이므로(6.4) "파라미터가 없다 = 꺼짐"으로 읽으면 기본값을 표현할 수 없다. **부재 = 기본값**(로그인 ON / 게스트 무시), `=0` 이 명시적 OFF, `=1` 이 명시적 ON 이다. 적용 필터 칩 줄(6.2)의 `내 나이대` ✕ 는 파라미터를 지우는 것이 아니라 `=0` 을 쓴다 — 지우면 기본값으로 되돌아가 칩이 다시 살아난다.
- 알 수 없는 값(`slot=BRUNCH`, `sort=cheap`)은 **에러가 아니라 기본값으로 떨어뜨린다.** URL 은 사용자가 직접 고칠 수 있고 공유도 되므로, 오타 하나로 빈 화면을 주지 않는다. `maxPrice` 는 `PRICE_CAPS` 에 있는 값만 받는다 — 임의 숫자를 받으면 필터 시트의 칩이 어떤 것도 선택되지 않은 상태로 뜬다.
- `maxPrice`는 **사용자 성별 기준 단일 축**이다. 여성이면 `femalePrice`, 남성이면 `malePrice`와 비교한다. 성별을 알 수 없으면(게스트) 가격 필터를 노출하지 않는다.
- `only20s`·`gender` 파라미터는 삭제됐다. 연령은 `eligibleOnly`로, 성별 모집 정책은 남녀 정원(`maleCapacity`/`femaleCapacity`)으로 대체된다.
- `sort=latest`는 **소개팅 회차의 `createdAt`**(등록일) 기준이다. 개최일 임박순이 아니고 주최사 입점일도 아니다. 홈 `새로 등록된 소개팅` 섹션과 같은 축이다.
- `sort=rating`은 **주최사 평점** 기준이다. 소개팅 회차에는 평점이 존재하지 않는다(7.4 참조). 정렬에는 원본 평균이 아니라 **베이지안 보정값**을 쓴다.
- `district`(구)는 `area`(동, 기존 지역 마스터)와 별개 축이다. `area`는 사용자 프로필·온보딩의 선호 지역(동 단위) 표시용으로 남기고, `district`는 지도/탐색 화면의 지역 필터(구 단위) 전용으로 새로 추가한 파라미터다.

### 6.2 상단 컨트롤

| 기능 | 사양 |
| --- | --- |
| 지역 선택 버튼 | `📍 서울 전지역 ▾` (또는 선택된 구 이름). 클릭 시 지역 선택 시트(6.3) | 
| 시간대 칩 | `전체 / 오전 / 오후 / 디너 / 심야` **단일 선택**. 해당 건수가 0인 슬롯은 칩 자체를 노출하지 않는다(지역 필터 6.3과 동일 원칙). `flex-wrap`으로 배치 — 가로 스크롤을 만들지 않는다. 좁은 화면에서 넘치는 칩(예: 필터 버튼)은 다음 줄로 자연스럽게 줄바꿈된다 |
| 필터 버튼 | 아이콘 + `필터`. 클릭 시 필터 시트(6.4). **적용 필터 칩 줄이 떠 있을 때는 개수를 붙이지 않는다** — 조건이 이미 칩으로 보이므로 `필터 · N`은 같은 정보의 중복이다. 칩 줄이 없을 때만 `필터 · N` |
| **적용 필터 칩 줄** | 현재 적용된 조건을 칩으로 나열하고 각 칩에서 ✕로 개별 해제. **조건이 0개면 줄 자체를 렌더하지 않는다**(높이 0). 아래 별도 항목 참조 |
| 결과 수 | `총 N개 소개팅` |
| 정렬 | `select` — 인기순(기본) / 최신순 / **평점 높은순** / 가격 낮은순 / 가격 높은순. **가격 정렬은 사용자 성별 기준값**(여성→`femalePrice`, 남성→`malePrice`)을 쓴다. 게스트는 가격 정렬 옵션을 숨긴다. 평점 정렬은 아래 별도 항목 참조 |
| 뷰 토글 | 세그먼트 `리스트 / 지도` |

- 활성 필터 개수 = 분위기 선택 수 + (일정 ≠ 전체 ? 1 : 0) + (규모 ≠ 전체 ? 1 : 0) + (가격 상한 설정 ? 1 : 0) + (신청 가능만 ? 1 : 0). **지역 선택과 자격 토글(`eligibleOnly`)은 이 카운트에 포함하지 않는다** — 둘 다 별도 UI로 항상 노출되므로 — 별도 버튼으로 항상 노출되므로 "필터 · N" 배지와 이중으로 세지 않는다.
- 위치 권한 허용 시 `거리순` 정렬 옵션 추가 필요 — 목업 미포함, **TBD**

**평점 높은순 정렬 (2026-09-02 신설)**

목록은 **소개팅**인데 평점은 **주최사**의 값이다(7.4). 그래서 정렬 규칙을 따로 정의한다.

| 항목 | 사양 |
| --- | --- |
| 정렬 키 | 주최사의 `ratingScore` — **원본 평균이 아니라 베이지안 보정값**이다 |
| 2차 정렬 | 동점이면 **개최일 가까운 순**. 같은 주최사의 회차가 뭉쳐 나올 때 최소한 임박한 것부터 보이게 한다 |
| 후기 부족 주최사 | 제외하지 않는다. 보정식이 전체 평균으로 끌어당겨 **중간에 놓는다** |
| 게스트 | 노출한다. 가격 정렬과 달리 인증 주체가 필요 없다 |

```
ratingScore = (C × m + 평점합) / (C + n)
  C = 신뢰 상수 (초기값 10)
  m = 전체 주최사 평균 (초기 고정값 4.3, 데이터가 쌓이면 실측값)
  n = 해당 주최사의 총 후기 수
```

**왜 하드 컷이 아니라 보정인가.** `후기 5건 이상만 정렬 대상`으로 자르면 절벽이 생긴다 — 4건짜리는 목록에서 아예 빠졌다가 5번째 후기가 달리는 순간 5.0으로 1위에 점프한다. 보정식은 후기 3건 · 평균 5.0을 `4.46`으로, 후기 50건 · 평균 4.6을 `4.55`로 계산해 **표본이 적은 만점이 표본이 많은 고득점을 이기지 못하게** 한다. 후기 0건 주최사는 `m`을 그대로 받아 맨 아래가 아니라 중간에 놓인다.

> ⚠️ **표시 평점과 정렬 순위가 어긋날 수 있다.** 화면에는 원본 평균(`4.6`)을 쓰고 정렬은 `ratingScore`로 한다. 평점이 높은데 아래에 있는 주최사가 생기므로, 문의가 오면 이 산식으로 답한다. `ratingScore`는 **화면에 절대 노출하지 않는다** — 두 숫자가 같이 보이면 설명할 수 없다.
>
> **같은 주최사 회차의 뭉침은 아직 막지 않는다.** 평점 1위 주최사가 회차를 5건 올려두면 상위 5개가 그 주최사다. MVP1은 주최사 수가 적어 체감되지 않으므로 2차 정렬만 두고, 카탈로그가 커지면 주최사당 연속 노출 상한을 건다 → 16장.

**적용 필터 칩 줄**

홈에서 `전체보기 >`로 진입하면 프리셋(`when=THIS_WEEK`, `eligibleOnly=1` 등)이 적용된 채로 도착한다. 이때 **적용된 조건이 화면에 보이지 않으면 "보이지 않는 필터"가 된다** — 결과가 왜 적은지 알 수 없고 풀 수도 없다. 필터가 없는 것보다 나쁘다.

| 항목 | 사양 |
| --- | --- |
| 위치 | 시간대 칩 줄 **아래**, 결과 수 **위** |
| 표시 대상 | 일정(`이번 주`/`그 이후`) · 자격(`내 나이대`) · 규모(`소수정예` 등) · 가격(`3만원 이하`) · 분위기(**선택한 태그마다 개별 칩**) · 모집 상태(`신청 가능만`) |
| 표시 제외 | **지역** — 상단 지역 버튼이 이미 `서울 {구}`로 보여준다. **시간대** — 상단 시간대 칩의 선택 상태가 이미 보여준다. **정렬** — 필터가 아니다 |
| 개별 해제 | 칩의 ✕ → 해당 URL 파라미터만 제거하고 즉시 재조회 |
| 초기화 | 칩이 2개 이상이면 줄 맨 뒤에 `초기화` 텍스트 버튼. 누르면 표시 대상 전부 해제(시간대·지역·정렬은 유지). **자격 칩도 대상이다** — 화면에 떠 있는 칩을 치우는 것이 이 버튼의 규칙이다. 필터 시트의 `초기화`(6.4)와 대상이 다르며, 어긋난 것이 아니라 각자 자기 화면에서 보이는 것만 되돌리는 것이다 (`decisions.md` 4.26) |
| 배치 | `flex-wrap`. 가로 스크롤을 만들지 않는다 |
| 접근성 | 각 ✕ 버튼의 `aria-label`은 `"{조건명} 필터 해제"` |

> `내 나이대` 칩은 로그인 사용자에게 기본 ON이다(6.4 자격 토글). 이 칩이 줄에 떠 있는 것 자체가 **"지금 네 출생연도로 걸러진 결과를 보고 있다"** 는 고지이자, 넓혀 보고 싶을 때의 해제 버튼이 된다. 게스트에게는 이 칩이 없다.
>
> 이 패턴은 원래 11.2 빈 상태에만 정의돼 있었다(`적용된 필터 칩 개별 해제(✕)`). 2026-09-01 개편으로 **결과 유무와 무관하게 상시 노출**로 승격한다.

**시간대 구간 정의**

| 슬롯 | 값 | 경계 |
| --- | --- | --- |
| 오전 | `MORNING` | ~ 12:00 |
| 오후 | `AFTERNOON` | 12:00 ~ 17:00 |
| 디너 | `DINNER` | 17:00 ~ 21:00 |
| 심야 | `LATE_NIGHT` | 21:00 ~ |

- 경계는 **시작 시각** 기준이다. 12:00 시작은 `오후`, 21:00 시작은 `심야`.
- `오전` 소개팅은 실제로 드물다. **건수가 0이면 칩을 노출하지 않는다** — 항상 빈 결과만 내놓는 칩은 노이즈다.
- 시간대는 사실상 **분위기의 대리 지표**다. 낮 소개팅과 심야 소개팅은 복장·주류·기대치가 다르다. 삭제한 카테고리 축의 역할을 여기가 대신하되, 시각은 모든 주최사 게시물에서 **결측 없이** 얻을 수 있다는 점이 다르다.

> ⚠️ **가로 스크롤 금지 원칙.** 2026-08-31 디자인 점검에서 시간대 칩·상태 필터 등 여러 화면의 `overflow-x:auto` 칩 줄이 "지저분하다"는 피드백으로 전부 `flex-wrap` 처리로 교체됐다(User v2/Admin/Provider/My/Admin Manage). 홈 화면의 카드 캐러셀(5.1의 "오늘 인기 소개팅" 등)은 의도된 스와이프 인터랙션이라 예외이며, 스크롤은 유지하되 스크롤바만 숨긴다. **새 화면에서 칩·필터를 가로 스크롤로 구현하지 않는다.**

### 6.3 지역 선택 시트 (바텀 시트)

MVP1은 서울시로만 서비스 범위를 한정하지만, 향후 경기·인천·대전·부산 등으로 확장할 계획이 있어 처음부터 **시/도 → 시/군/구 2단 계층 구조**로 설계한다.

| 단 | 구성 | 사양 |
| --- | --- | --- |
| 1단 시/도 | 서울 / 경기 / 인천 / 대전 / 부산 | **서울만 선택 가능.** 나머지는 "오픈 예정" 라벨과 함께 비활성(disabled) 처리 |
| 2단 시/군/구 | 서울 전지역 + 실제 소개팅이 있는 구만 나열(예: 강남구·노원구·동대문구·마포구·성동구·송파구 …) | 구별 소개팅 건수 표시(`N곳`). 소개팅이 없는 구는 목록에 노출하지 않는다 |

| 기능 | 동작 |
| --- | --- |
| 진입 | 상단 지역 선택 버튼 클릭 |
| 시/도 전환 | 서울 외 항목 클릭 시 무반응(비활성) — 추후 오픈 시 이 자리에서 바로 전환 가능하도록 구조만 선반영 |
| 구 선택 | 단일 선택. 선택 즉시 상단 버튼 라벨이 `서울 {구}`로 바뀌고 지도/리스트 결과가 갱신 |
| 닫기 | 우상단 X 또는 딤 클릭 |

> 필터 시트(6.4)와 별개의 진입점이다. 지역은 "어디서" 축, 필터 시트는 "어떤 조건" 축으로 UX상 분리한다.
>
> **비즈니스 메모** — 서비스가 서울 외 지역으로 확장될 때, 결제(신청비 등)를 지금처럼 주최사 외부 페이지에 100% 위임하지 않고 MeetMap이 자체 처리하는 방향으로 분리할 계획이 있다(별도 `payment-service`, MSA 구성). 프론트 영향은 크지 않지만 7.3 외부 신청 이동 정책과 13장 API 설계 시 결제 주체 전환 가능성을 염두에 둔다 → 16장에 추적.

### 6.4 필터 시트 (바텀 시트)

필터는 성격이 다른 **3층 구조**다. 1층은 칩이 아니라 프로필 기반 자동 적용이다.

**1층 · 자격 — "내가 신청이라도 할 수 있는가"**

시트 최상단에 토글 1개로 노출한다. 칩 그룹이 아니다.

| 요소 | 사양 |
| --- | --- |
| `내가 신청 가능한 것만` 토글 | 프로필 `birthYear`가 `birthYearFrom~To`에 들고, 내 성별 정원이 0이 아닌 건만. URL `eligibleOnly=1`. **로그인 사용자 기본 ON** |
| 게스트 | 토글 자체를 숨기고 **전건을 보여준다** (판단 근거가 없다) |
| 출생연도 미입력 로그인 사용자 | 게스트와 같게 다룬다 — 토글을 숨기고 전건. 인트로에서 `나중에 할래요`(3.3)를 고르면 실제로 생기는 상태다 |
| **토글 OFF** | 자격 밖 회차가 섞여 들어온다 → 해당 카드에 **자격 미충족 표시**를 붙인다 (아래) |

> 연령대를 칩 필터로 두지 않는 이유: 92년생이 `95~02년생 전용` 소개팅을 봐도 아무 의미가 없다. 온보딩(3.4)에서 이미 받은 출생연도로 **처음부터 걸러 보여주고**, 넓혀 보고 싶을 때 끄게 하는 것이 맞다.

**자격 미충족 표시는 토글이 꺼져 있을 때만 그린다 (2026-09-04).**

토글이 켜져 있으면 남은 건이 전부 자격을 만족하므로 표시가 늘 같은 값이 된다 — 홈에서 상태 배지를 뺀 것과 같은 이유다(`decisions.md` 4.23). 껐을 때만 의미가 생긴다.

| 항목 | 사양 |
| --- | --- |
| 문구 | `내 나이대 아님` — `참가 불가`를 쓰지 않는다. 정원이 안 맞아 못 가는 경우도 같은 표시를 받는데 "불가"는 거절로 읽힌다 |
| 붙는 자리 | 리스트 카드의 배지 줄(6.5). 메타 줄의 `N~N년생` 은 그대로 둔다 — 표시가 **왜** 떴는지 그 줄이 답한다 |
| 게스트 | 붙이지 않는다. 자격을 판정할 근거가 없다 |

> 이 표시가 없으면 사용자가 카드의 `90~96년생` 과 자기 출생연도를 **직접 대조**해야 한다. 상단의 적용 필터 칩 줄(6.2)은 토글이 **켜져 있을 때** `내 나이대` 칩으로 고지하지만, 끄면 그 칩이 사라져 아무 고지 없이 섞인다.

**2층 · 일정 · 위치 — "갈 수 있는가"**

| 그룹 | 항목 | 선택 방식 |
| --- | --- | --- |
| 일정 | 전체 / 이번 주 / 그 이후 | **단일 선택** |
| 시간대 | 전체 / 오전 / 오후 / 디너 / 심야 | **단일 선택** (상단 컨트롤 6.2와 동일 상태 공유) |
| 지역 | — | 필터 시트가 아닌 **별도 진입점**(6.3) |

**3층 · 취향 — "가고 싶은가"**

| 그룹 | 항목 | 선택 방식 |
| --- | --- | --- |
| 규모 | 전체 / 소수정예(5:5 이하) / 표준(6:6~9:9) / 대규모(10:10 이상) | **단일 선택** |
| 분위기 | 차분한 / 트렌디한 / 활동적인 / 편안한 / 고급스러운 / 네트워킹 | **다중 선택 (OR 조건)** |
| 가격 | 상한 칩 — 3만원 / 5만원 / 7만원 / 제한 없음 | **단일 선택.** 사용자 성별 기준값과 비교 (6.1). 게스트는 그룹 자체를 숨김 |
| 모집 상태 | `신청 가능만 보기` | 토글 1개. `status === '신청 가능'` |

| 기능 | 동작 |
| --- | --- |
| 초기화 | 2·3층 전부 기본값으로 — **시간대(2층)를 포함한다.** **1층 자격 토글은 초기화 대상이 아니다** (개인 조건이지 필터가 아니다). 상단 칩 줄의 `초기화`(6.2)와 대상이 다르다 → `decisions.md` 4.26 |
| 결과 보기 | 라벨 `N개 결과 보기` — 실시간 결과 수 반영, 클릭 시 시트 닫힘 |
| 닫기 | 우상단 X 또는 딤 클릭 |
| 최대 높이 | `82vh` + 내부 스크롤 |

> 목업 로직상 **필터는 실시간 반영**된다(적용 버튼 없이 칩 선택 즉시 결과 수 변동). 이 동작을 유지한다.
>
> **2026-09-01 개편.** 이전 필터는 `분위기 / 20대 위주 / 성별 조건` 3그룹이었다. `20대 위주`는 연령이 '나이'가 아니라 **출생연도 범위**라 성립하지 않고, `성별 조건`은 남녀 정원이 애초에 분리 모집되므로 필터 축이 아니다(둘 다 목업에서 결과 0건이던 원인). `genderPolicy` 필드는 **삭제**한다.

### 6.6 지도 뷰

| 기능 | 사양 |
| --- | --- |
| 지도 영역 | 높이 `calc(100vh - 250px)`, 최소 420px. **실제 지도 SDK 연동 예정**(목업은 플레이스홀더) |
| 마커 라벨 | **시각만 표시**(예: `19:00`). 기존에는 `시각 · 소개팅명`을 함께 붙였으나 2026-08-31 수정으로 소개팅명은 제거 — 상세 정보는 마커 탭 시 뜨는 마커 시트에서 확인 |
| 선택 마커 | 강조색(`--color-accent`) + `z-index` 상승 |
| 줌 컨트롤 | 지도 우측 하단 `+ / −` 버튼. 확대/축소 한계에 도달하면 해당 버튼 비활성 스타일로 전환 |
| 마커 클릭 | 하단 마커 시트 오픈 |
| 마커 소스 | 현재 적용된 지역(6.3)·필터(6.4) 결과와 동일 목록 |
| **위치 정밀도 표시** | `locationPrecision`에 따라 마커 모양을 구분한다 — `EXACT`(정확한 주소): 채운 마커 / `STATION`(지하철역 기준): 테두리 마커 + 시트에 `{stationName} 인근` / `DISTRICT`(구 중심): 반투명 마커 + 시트에 `{district}` |
| 클러스터링 | 목업 미정의 — **TBD** |

**마커 바텀 시트**

| 요소 | 내용 |
| --- | --- |
| 헤더 | 썸네일 88px + 상태 배지 + 제목 + `주최사 · 날짜 시각` |
| 태그 3종 | `N~N년생` / `남 N · 여 N` / 규모(`소수정예` 등) |
| 하단 | 가격(세리프) + `신청 페이지로 이동` |

> **위치 정밀도를 시각적으로 구분하지 않으면 안 된다.** 인스타 게시물에 정확한 장소가 없는 소개팅이 상당수이고, 이런 건은 지하철역 또는 구 중심에 핀을 찍는다. 정확한 주소처럼 보이면 사용자가 헛걸음한다. `EXACT`가 아닌 건수는 곧 **주최사 컨택 우선순위**이기도 하다.
>
> 마커 시트의 `신청 페이지로 이동`은 소개팅 상세의 `신청하기`와 동일하게 **외부 이동 확인 모달(7.3)** 을 경유해야 한다. 목업은 시트만 닫히지만, 조건 고지 누락은 정책 위반 소지가 있어 모달 경유로 정의한다.
