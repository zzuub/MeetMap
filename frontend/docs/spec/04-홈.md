## 5. 홈 — `/`

### 5.1 구성 (상단 → 하단)

1. 앱 헤더 (로고 / 검색 / 알림)
2. 헤드라인 + 추천 기준 안내
3. 지도 프로모 카드
4. 섹션 A — 이번 주 인기 소개팅 (가로 스크롤)
5. 섹션 B — 내 나이대 소개팅 (가로 스크롤)
6. 섹션 C — 새로 등록된 소개팅 (세로 리스트)
7. 하단 내비게이션

> **퀵 필터 칩 바는 삭제됐다 (2026-09-01).** 홈에 필터를 두지 않는다. 근거는 5.4.

### 5.3 섹션별 데이터 규칙

| 섹션 | 정렬 / 필터 | 카드 형태 | 표시 항목 |
| --- | --- | --- | --- |
| 이번 주 인기 소개팅 | **모집 중** + 이번 주 개최 + `popularity` 내림차순, 최대 6건 | 대형 카드(196px) | 썸네일 + 찜 버튼, 시간대 배지, 제목(2줄), 일시, 가격 |
| 내 나이대 소개팅 | **모집 중** + 프로필 `birthYear`가 `birthYearFrom~To`에 포함, 최신순 6건 | 대형 카드 | `{N}년생 참가 가능` 배지, 제목, 정원(`남 N · 여 N`), 가격 |
| 새로 등록된 소개팅 | **모집 중** + 등록일 내림차순, 최대 4건 | 소형 가로 카드 | 썸네일(62px), 제목, `주최사 · 시간대 시각`, 가격 |

- 인기순(`popularity`) 산식 — **TBD**
- **섹션 B는 로그인·프로필 입력이 전제다.** 게스트이거나 `birthYear` 미입력이면 섹션 B를 숨기고 `새로 등록된 소개팅`을 위로 올린다.
- 건수가 0인 섹션은 **줄 자체를 그리지 않는다.** 제목과 `전체보기 >` 만 남은 줄은 빈 상태가 아니라 결함으로 읽힌다.

**홈은 마감된 소개팅을 아예 내리지 않는다 (2026-09-04).** 세 섹션 모두 `status: '신청 가능'` 만이다.

| 근거 | 설명 |
| --- | --- |
| **홈에는 상태 필터가 없다** | 마감 건이 섞여도 사용자가 걷어낼 수단이 없다. 필터는 탐색 한 곳뿐이라는 5.4 의 뒷면이다 |
| **홈은 큐레이션이다** | "우리가 골라 보여준다"는 자리에 신청할 수 없는 것을 고를 이유가 없다. 마감 회차를 보고 싶으면 탐색에서 상태 필터를 풀면 된다(기본값이 `ALL` 이다) |
| **표시 항목이 세 섹션에서 서로 달랐다** | 상태 배지가 섹션 A 에만 있어 B·C 에서는 **마감된 소개팅이 신청 가능해 보였다.** 배지를 세 곳에 늘리는 것보다 마감을 거르는 쪽이 화면도 규칙도 단순하다 |

그래서 **섹션 A 의 상태 배지를 표시 항목에서 뺐다.** 전부 `신청 가능` 이라 같은 값만 찍히는 배지가 되고, 배지가 있으면 "없는 것도 있나 보다"라는 잘못된 기대를 만든다.

> ⚠️ **`compact` 카드는 찜 목록과 공용이고, 찜 목록에는 상태 배지가 필요하다**(9장). 찜한 소개팅은 마감돼도 목록에서 사라지지 않기 때문이다. 그 배지는 찜 목록을 만들 때(P2-8) 넣는다 — 홈은 마감을 받지 않으므로 여기서는 그려지지 않는다.

> **섹션 B·C는 2026-09-01 도메인 재정의로 교체됐다.** 이전 안은 `여성 신청 많은 소개팅`(성비순)과 `지금 신청 가능한 소개팅`(잔여석 기준)이었다. 로테이션 소개팅은 **정원이 남녀 고정(7:7 등)이고 선착순이 아니라 주최사 심사 선발**이라, 성비도 잔여석도 존재하지 않는 값이다(12장 참조).

### 5.4 홈에 필터를 두지 않는다

**퀵 필터 칩 바(`오늘 / 점심 / 저녁 / 심야 / 3만원 이하`)를 삭제한다.** 홈의 필터 진입점은 없다.

| 근거 | 설명 |
| --- | --- |
| **칩이 필터처럼 생겼는데 링크로 동작했다** | 누르면 결과가 걸러질 것 같은데 실제로는 탐색 화면으로 이탈한다. 이 어긋남이 사용자가 체감한 문제의 정체다 |
| **필터는 한 군데만 있어야 한다** | 탐색 화면에 3층 구조 필터(6.4)가 이미 있다. 홈에 축이 겹치는 반쪽 필터를 두면 두 벌을 따로 유지해야 한다 — 2026-09-01 카테고리 축 개편에서 목업 10종을 전부 뒤진 비용이 그 실증이다 |
| **홈과 탐색은 역할이 다르다** | 홈은 큐레이션("우리가 골라 보여준다"), 탐색은 필터("네가 조건을 건다"). 칩은 탐색의 문법을 홈으로 끌고 들어온다 |
| **세로 공간** | 430px 화면에서 히어로 + 지도 카드 + 칩 줄 + 섹션 3개는 첫 화면에 카드가 안 들어온다 |
| **개인화는 고정 섹션이 담당한다** | `내 나이대 소개팅`(섹션 B)이 상설로 있으므로 칩으로 같은 걸 누를 이유가 없다 |

홈에서 화면을 떠나는 경로는 **`전체보기 >`(3개)와 지도 프로모 카드**뿐이다. 둘 다 이동한다는 사실이 라벨과 형태로 드러나므로, 칩처럼 기대를 배신하지 않는다.

> **되돌리기 조건.** 섹션이 5개 이상으로 늘어 홈이 스크롤 지옥이 되거나, 로그 분석에서 홈 → 탐색 이탈률이 지나치게 낮게 나오면 그때 재검토한다. 그 경우에도 칩을 되살리기보다 **섹션 자체를 개인화하는 방향**을 먼저 본다.
