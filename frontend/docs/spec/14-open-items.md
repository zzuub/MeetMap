### 사양 문서 갱신 대기 — 구현이 문서보다 앞서 나간 자리

구현이 사양과 다르게 굳었고 **근거는 `docs/decisions.md` 에 있는데 사양 문서는 옛 문장을 그대로 들고 있는** 항목이다. 문서만 읽는 사람에게는 드리프트가 안 보이므로 여기 모은다.

## 17. 구현 우선순위 (제안)

| 단계 | 범위 | 근거 |
| --- | --- | --- |
| **P0** | 공통 셸(헤더·탭·토큰) → 홈 → 탐색 리스트 → 소개팅 상세 → 외부 신청 모달 | 핵심 탐색-전환 퍼널. 여기까지가 서비스의 최소 가치 |
| **P1** | 온보딩 + 위치 권한 + 찜 + 검색 | 개인화·재방문 기반 |
| **P2** | 탐색 지도 뷰 + 마커 시트 + 비교함 | "지도에서 비교"라는 제품 차별점 |
| **P3** | 마이 + 알림함 + 알림 설정 | 리텐션 |
| **P4** | 후기 목록 + 후기 작성 + **주최사 소개 페이지** | 참여 인증 연동 선행 필요. 주최사 페이지는 후기가 쌓여야 값이 생긴다 |

> **주최사 소개 페이지(7.4)의 우선순위는 P4 다.** 페이지 자체는 P1 의 데이터 모델 변경(`provider` 객체 승격)만 끝나면 만들 수 있지만, 평점 요약과 후기 목록이 비어 있으면 프로필과 회차 목록만 남는다. 후기 기능과 같은 단계에 두는 것이 맞다.
>
> 다만 **`provider` 객체 승격과 `rating`/`reviewCount` 삭제는 P1 에서 먼저 한다.** 카드·상세·비교함이 전부 이 필드를 지나가므로 나중으로 미룰수록 고칠 자리가 는다.
