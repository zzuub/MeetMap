### 2026-09-10 · [#25](https://github.com/zzuub/MeetMap/issues/25) · P2-1~P2-5 2차 리뷰 반영
**세 번 연속으로 같은 실수를 했다 — 이번엔 쓰기를 세고 읽기를 안 셌다**

리뷰가 둘을 짚었고 둘 다 맞다. 하나는 가드 구멍, 하나는 **계약을 지켜도 작동하지 않는 상태**다.

**① `done/page.tsx` 가 가드를 안 불렀다** → 4.49 정정. 1차 리뷰 반영에서 `requireFunnelSession` 을 떼면서 "부르는 자리가 셋"이라고 적었는데 **넷이어야 했다.** `done` 은 퍼널 단계(3.5)이고 `<Link>`(인트로의 `나중에 할래요` · 프로필의 `건너뛰기`)로만 도달하는데다 **프로필을 실제로 조회한다.** 4.49 가 측정한 "레이아웃 재실행 보장 없음" 케이스에 정확히 걸린다.

빠뜨린 이유가 정확히 기록할 값이 있다 — **기준을 "쓰기를 하는 자리"로 잡았기 때문**이다. `done` 은 폼이 아니라 조회라 그 기준에 안 걸렸고, 내가 적은 한계 서술("폼이 그려지는 것까지는 못 막는다")도 이 경우를 안 덮었다. 기준을 **"세션에 딸린 일을 하는가"** 로 바꾸고 **단계 넷을 표에 전부 적었다** — `intro` 가 `없음` 으로 표에 남아 있는 것이 요점이다. 빠진 칸이 아니라 **비어 있는 칸으로 보여야** 다음 사람이 다시 안 빠뜨린다.

**② 약관 POST 의 세션 갱신은 계약을 지켜도 작동하지 않는다** → 4.50. 1차 반영에서 "백엔드가 `Set-Cookie` 로 토큰을 내려야 한다"를 `endpoints.ts` 에 계약으로 적었는데, 리뷰가 `fetchClient` 를 따라가 **받을 자리가 없다**는 것을 찾았다. `agreeTermsAction` → `saveTerms` 는 Server Action 안에서 나가는 **서버→서버 fetch** 이고 `fetchClient` 는 `response.headers` 를 어디서도 안 읽는다(확인했다). 백엔드가 계약을 완벽히 지켜도 그 헤더는 Next 서버에서 끝난다.

**"프론트가 위반을 감지 못 한다"가 아니라 "계약을 지켜도 작동하지 않는다"** 라 등급이 다르다. OAuth 콜백은 브라우저가 직접 리다이렉트를 타서 멀쩡하고, 이 리포에서 차이가 나는 자리는 **약관 POST 하나뿐**이다.

**지금 구현하지 않는다** — 실 백엔드가 없어 눌러볼 수 없고(3.1 인증 실패 토스트를 안 만든 기준과 같다), 무엇보다 어느 모양으로 받을지가 백엔드 응답에 달렸다. 대신 두 선택지(① `Set-Cookie` 릴레이 ② 응답 본문으로 토큰)를 계약서 자리(`endpoints.ts`)에 적고 `phase2-notes.md` 막힌 것에서 **이번 Phase 에서 가장 무거운 미결**로 올렸다. 리뷰가 제안한 "제출 후 재조회로 확인"은 **릴레이 뒤에야 의미가 있다** — 지금 붙이면 항상 갱신 전 세션을 봐서 오탐이 된다.

**세 번 반복된 형태라 번호를 붙였다** → 4.51. #24 는 화면만 세고 컨트롤을 안 셌고(표면 2→3), #25 는 화면을 세고 시간을 안 셌고(진입 경로 7→8), 이번엔 쓰기를 세고 읽기를 안 셌다(호출 3→4). 셋 다 잊어버린 것이 아니라 **세는 축을 하나 빠뜨린 것**이다. 그래서 표를 적을 때 **축을 먼저 적고 빈 칸도 남긴다** — `emptyRelaxation.test.ts` 가 `Record` 로 축 14개를 강제한 것(4.42)과 같은 발상이고, 타입으로 못 강제하는 자리에서는 표가 그 일을 한다.

리뷰가 확인만 하고 넘긴 `getServerSession.ts` 의 `USE_MOCK` 분할은 그대로 뒀다 — 판정 범위를 함수 하나로 좁힌 것으로 모순이 해소됐다는 판단에 동의한다.

검증: `eslint`·`tsc`·`vitest 407건`·`next build`·`assert-dynamic-routes`·`TZ` 2종. 게스트가 `/onboarding/done` 을 열면 로그인으로 떨어지는 것을 실제로 확인했다.


### 2026-09-10 · [#25](https://github.com/zzuub/MeetMap/issues/25) · P2-1~P2-5 코드리뷰 반영
**표를 먼저 세서 화면은 다 셌는데, 시간축을 안 셌다**

리뷰가 셋을 짚었고 셋 다 손댔다. 구현 결함은 하나도 아니었다 — 전부 **검증되지 않은 전제**였다.

**① 퍼널 가드가 소프트 내비게이션에서 다시 도는지 확인이 안 됐다.** 주장을 좁히기 전에 **측정했다** — 레이아웃에 로그를 심고 개발 서버 stdout 을 읽었다 → 4.49. 하드 로드와 Server Action 의 `redirect()` 에서는 항상 돌지만 **`<Link>` 이동에서는 보장되지 않는다.** 두 번 측정해 답이 달랐다(한 번은 아예 안 찍혔고, 한 번은 프리페치로 보이는 호출이 있었다). "안 돈다"도 과장이라 `보장되지 않는다` 로 적었는데, 결론은 오히려 분명해진다 — **타이밍에 기대는 가드는 가드가 아니다.**

이게 4.45 의 진입 경로 표에 없던 여덟 번째 줄이다: **퍼널 안에서 세션이 죽는 경우.** 진입할 때는 세션이 있었으니 표의 어느 줄에도 안 걸린다. 화면은 다 셌는데 시간축을 안 센 것이 지난 판의 "표면을 둘로 셌는데 셋이었다"와 같은 종류의 누락이다.

판정을 `(funnel)/_guard.ts` 의 `requireFunnelSession` 하나로 떼고 **쓰기를 하는 액션 둘이 한 번 더 부른다**(Server Action 은 매번 서버에서 돈다). 화면 넷에 각각 적는 안과 `checkAccess` 로 올리는 안은 받지 않았다 — 후자는 `PUBLIC_PREFIXES` 가 `/onboarding` 전체를 열어 두어 "아래는 막고 자신은 열어라"를 프리픽스 한 줄로 못 쓴다. **남는 것을 정확히 적었다**: 폼이 그려지는 것은 못 막고, 세션 없는 저장과 실 모드 401 의 잘못된 안내를 막는다. 액션 가드가 실제로 도는 것은 로그로 확인했다(제출 → 액션 자신 + `redirect()` 후 레이아웃, 둘 다 찍힌다).

**② `getServerSession.ts` 가 자기 파일 안에서 모순이었다.** 주석은 "목/실 분기는 `readSession` 안에 있다, 여기서 다시 판정하지 않는다"인데 바로 아래 `getAccessToken` 이 `USE_MOCK` 을 또 본다. 코드를 지우지 않고 **주석을 정확히 고쳤다** — 둘은 성격이 다르다. 하나는 "세션을 어디서 읽나", 다른 하나는 **"토큰을 밖으로 내보낼까"** 다. 실 모드에서 쓰던 `meetmap_at` 이 남은 채 목 모드로 내려오면 목 구현이 값을 무시한다는 사실에만 기대게 되는데, 목 구현은 여럿이고 늘어난다.

**③ 빈 `finishSignUp` 이 백엔드 계약에 기대는데 그 계약이 어디에도 없었다.** `POST /users/me/terms` 가 약관을 저장하면서 **갱신된 토큰을 `Set-Cookie` 로 심어 `isNewUser` 를 내려야** 한다. 안 지키면 실 모드에서 기존 회원이 로그인할 때마다 약관 화면으로 되돌아오는데 **프론트에는 확인할 수단이 없다** — 목에 재현 경로가 없어 테스트 407건 중 아무것도 못 잡는다. 근거가 주석 한 줄뿐이었으므로 **프론트-백 계약서 자리인 `shared/api/endpoints.ts` 의 `user.terms`** 에 옮겨 적고, 포트 주석과 `phase2-notes.md` 막힌 것 표에서 그리로 가리킨다.

리뷰가 확인만 하고 넘긴 것 둘은 그대로 뒀다. `safeRedirect` 는 추가 우회가 없고 소비 지점도 하나가 맞다(로그인 화면이 hidden input 에 넣기 전에 한 번 통과시키는 것은 중복 검증이지 별도 경로가 아니다). `hasViewer` 게이트도 재판정 자리가 없다. 리뷰가 덤으로 찾은 조합 — 역할 스위치를 켠 채 로그인하면 실제로는 USER 인데 `찜`·`마이` 가 막힌다 — 은 "스위치가 로그인을 이긴다"의 파생이라 `phase2-notes.md` 개발 팁에 한 줄 더했다.

검증: `eslint`·`tsc`·`vitest 407건`·`next build`·`assert-dynamic-routes`·`TZ` 2종. 가드 변경은 순수 함수가 아니라 테스트가 아니라 **로그로 확인**했다.

### 2026-09-10 · [#25](https://github.com/zzuub/MeetMap/issues/25) · P2-1~P2-5 온보딩 퍼널
**로그인 버튼에 목적지를 주려고 포트를 하나 더 세웠다. 그리고 `?redirect=` 를 처음으로 읽었다**

Phase 2 DoD 의 앞쪽(`신규 가입자가 소셜 로그인부터 홈 진입까지 완주한다`)을 닫았다. 화면 다섯 장(3.1~3.5)과 그것을 떠받치는 포트 둘(`accountApi`·`userApi`)이 붙었다.

**착수 전에 셋을 정했다.**

**① 로그인 버튼은 무엇을 하나** → 4.43. `eventApi`(4.3)와 같은 형태의 `accountApi` 포트를 세웠다. **`meetmap_mock_role` 에 묶는 안은 받지 않았다** — 그 쿠키가 만드는 세션은 `isNewUser` 가 항상 거짓이라 묶는 순간 3.1 의 신규 분기가 **만들자마자 죽고**, 애초에 개발용 역할 스위치이지 화면이 아니다("어느 역할로 로그인할래요"를 사용자에게 묻게 된다 — 역할은 진입점이 정한다는 dev-plan 3.3 과 어긋난다). ⚠️ **`eventApi` 와 한 군데가 다르다**: 돌려주는 값이 `REDIRECT | SESSION` 유니온이다. 실 모드는 브라우저를 소셜로 넘기고 세션은 콜백에서 오는 반면 목 모드는 그 자리에서 세션이 생긴다 — 한 모양으로 누르면 실 구현이 거짓말을 한다.

**② `viewer` 주입을 이번에 하나** → 4.44. **했다.** 미루는 쪽이 결함을 남기기 때문이다: P2-1 이 로그인을 실제로 가능하게 만드는 순간 `isGuest: session === null` 이 틀린 판정이 된다 — **프로필을 건너뛴 로그인 사용자**에게 가격 정렬·자격 필터가 열리고, 목에서는 `MOCK_VIEWER`(1996·F)가 대신 판정해 **사용자가 입력한 적 없는 조건이 조용히 걸린다.** 그걸 닫으려면 두 화면이 어차피 프로필을 읽어야 하고, 읽고도 안 넘기면 프로필을 방금 저장한 사용자가 저장 안 된 화면을 본다. 게이트 이름을 **`hasViewer` 로 바꾼 것이 요점**이다 — 값만 갈아끼우면 다음 사람이 다시 세션을 넣는다.

**③ `(onboarding)` 의 error/loading/not-found** → 4.47. `error.tsx` 는 붙였고 근거는 **화면 수가 아니라 출구**다 — 탭도 헤더도 없는 유일한 셸이라 에러 카드가 `홈으로 가기` 를 직접 준다. `loading.tsx` 는 4.41 의 "화면마다"에서 벗어나 **퍼널 공통 한 장**이다(넷 다 같은 모양이고 흉내낼 콘텐츠가 없다). `not-found.tsx` 는 **안 만들었다** — 그룹에 동적 세그먼트가 없어 `/onboarding/{오타}` 는 루트 `not-found` 로 가고 그게 맞는 문구다.

**규칙보다 먼저 진입 경로를 표로 셌다** → 4.45. 지난 판에서 실패 표면을 둘로 세고 셋이었던 것이 화면과 표면을 같은 것으로 센 탓이라, 이번에는 신규 가입 / 기존 로그인 / `checkAccess` 리다이렉트 / 손으로 친 URL / 중간 단계 새로고침을 먼저 적고 시작했다. 표에서 나온 판단 둘:

- **`/onboarding` 은 세션을 보고 리다이렉트하지 않는다.** 완료한 사용자를 홈으로 보내면 ① 퍼널 중간에 뒤로가기로 돌아온 사용자가 갇히고 ② `기존 회원은 홈으로` 분기를 **누를 방법이 사라져** ①에서 피하려던 죽은 분기가 다시 생긴다. `isNewUser` 판정은 **로그인 액션 한 곳**이다
- **퍼널 가드는 화면 넷이 아니라 `(funnel)` 그룹 레이아웃에 뒀다.** `PUBLIC_PREFIXES` 가 `/onboarding` 전체를 열어 둬서 **세션 없이 프로필 폼에 도달하는 구멍**이 있었다. ⚠️ 레이아웃이 모든 이동에서 다시 도는 것은 아니라 리뷰 반영에서 쓰기 자리를 보강했다 → 4.49

**`?redirect=` 는 P0-7 부터 붙어 나갔고 아무도 안 읽고 있었다.** 읽는 순간 `redirect=https://evil.com` 이 통한다. `safeRedirect` 하나가 **소비 시점**에 판정한다 — `proxy.ts` 가 만든 값도 믿지 않는다(주소창에 직접 칠 수 있다). 막을 것을 열거하지 않고 허용 조건을 좁게 적었고(`/` 로 시작 + 둘째 글자가 `/`·`\` 아님 + 파싱 후 오리진 유지) 적대적 입력 10종을 테스트가 잠근다. 온보딩 경로를 빼는 것은 보안이 아니라 **루프 방지**다.

**입력값은 단계마다 제출한다** → 4.48. 2.4 의 `마지막 단계에서 일괄 제출` 에서 벗어났다 — 완료 화면에 제출 버튼이 없고(닫으면 약관 없는 계정이 남는다), `나중에 할래요` 가 프로필을 건너뛰며, 무엇보다 **3.5 동적 문구가 새로고침을 못 견딘다**(방금 프로필을 채운 사용자가 `아무것도 안 골랐다`는 문구를 본다). 완료 화면은 서버에서 프로필을 다시 읽는다. 그래서 **`건너뛴 사용자` 를 따로 저장하지 않는다** — `프로필 없음`이 곧 그 상태이고, 값을 둘로 두면 어긋난다.

**세 라운드 연속으로 뚫린 이유가 같다.** 방어선을 만든 뒤 *떠오른 형태만* 확인했다 — 1차는 강제 장치 없이 문서만, 2차는 점 표기만, 3차는 리뷰가 불러준 다섯 개만. 우회 공간을 먼저 나열한 적이 없다.

**그래서 목록을 코드로 고정했다** — `model/outboundGuard.test.ts` 가 ESLint Node API 로 13가지 형태를 실제로 린트한다. 새 형태가 생각나면 문서가 아니라 그 표에 줄을 더한다. 선택자 5분기를 하나씩 지워 각각이 일하는 것도 확인했다.

`caught: false` 두 줄(`Object.values`·문자열 조합)은 **포기가 아니라 등급 선언**이다 — 코드에 그 글자가 없어 정적 선택자로 원천 불가능하고, 누가 규칙을 넓혀 잡히게 되면 테스트가 실패해 4.38 의 "실수 방지 등급" 문장을 함께 고치게 한다.
